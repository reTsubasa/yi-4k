# 1.10.7 隐藏启动区：SYS PTB 的低地址 RAM 候选

本轮新找到的是**本机 1.10.7 代码里的 SYS PTB 内存定位合同**，不是新取得的启动区字节或恢复入口。它给出下一条具体调查路径：先核验固定指针并取得很小的已加载 PTB RAM 副本，尝试识别 BOOTSTRAP、BOOTLOADER、FW_UPDATER 的长度、装载地址和数据 CRC。无需先运行通用 USB loader，也无需调用 NAND 装载或初始化函数。

本轮仅读取现存文件、执行主机合成 CPU 模型、写出独立报告。没有访问相机、枚举 USB、接线、读取 `/dev/mem`、启动目标程序或修改设备。没有修改 Android、预录或现有顶层索引。

## 新旧证据的区别

| 表 | 现有来源 | 新发现 | 当前限制 |
| --- | --- | --- | --- |
| USER PTB | 已有 `VENDOR_DATA` 逻辑 NAND 捕获，SHA-256 `69c4fcd4c096e0b02b0c0303483c11a364cafc0c46fe5aefaf73983fff7f3844`；13 条记录及 CRC 已知 | RTOS 代码的两组静态指针都给出 RAM 地址 `A0001800`；表长 `0x354` | 本轮只是把旧捕获 `[0,0x354)` 当解析器控制；没有读到该 RAM 地址 |
| SYS PTB | 尚无本机表字节；此前只有公开 BLD 的结构参考 | **本机 1.10.7** 分区选择、CRC、NAND 装入和更新器代码一致指向 `A0001400`；表长 `0x1D0`，有 3 条启动分区记录 | 指针是镜像初始值，运行时仍待核验；没有隐藏分区内容、NAND/OOB 或独立恢复证明 |

代码输入固定为已有本机 `rtos-window.bin`，基址 `A0100000`，SHA-256：

`eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`

不是将公开 1.10.52 BLD 地址直接移植到设备。公共 USB CLI 的板级初始化和字段冲突仍见此前两份报告，本轮不重复以其作为可执行候选。

## 两条独立的指针来源

以下四个词位于固定 RTOS 存储镜像中，均由本轮脚本按原始字节核验：

| 指针词地址 | 镜像值 | 使用者 |
| --- | --- | --- |
| `A078B600` | `A0001400` | NAND 分区选择器与表装入路径 |
| `A078B604` | `A0001800` | 同上，用户分区表 |
| `A06F27F8` | `A0001400` | 更新器 `A0298C8C` 的系统分区记录访问 |
| `A06F27F4` | `A0001800` | 同上，用户分区记录访问 |

原厂选择器 `A0492DC8` 对 `r0==0` 接受索引 `0..2`，返回 `*[A078B600]+0xC+index*0x40`；`r0!=0` 接受 `0..12`，返回 `*[A078B604]+8+index*0x40`。超出范围返回零。脚本直接在 Unicorn 执行原始函数，15 个选择/边界场景全部通过，未替换任何目标服务。

`A0298C8C` 的另一路原码使用 `A06F27F8/A06F27F4` 作相同记录计算。其系统分区配置 `A05ACDFC` 的三个名称指针依次为 `A05ACEB4/A05ACEC0/A05ACECC`，原始字符串为 `BOOTSTRAP`、`BOOTLOADER`、`FW_UPDATER`。这是表项名称和顺序的静态来源，实际 RAM 表仍须按这些名称核验。

保留的 Ghidra 直接引用索引没有标出对这四个指针词的 WRITE 引用；这不是不可变证明。别名、间接写、冷启动与休眠恢复可能不在索引覆盖内。不能只凭存储镜像初值就跨地址读任意运行时指针。

## 表的来源与副本性质

本机 `A048498C` 先调用 NAND 页读取包装 `A04831F0`，成功后通过 `A029C680` 将 `0x1D0` 字节复制到 `*[A078B600]`。页范围来自全局 `A1A39C68/A1A39C6A`。本轮未读这些运行时字段，也未推断实际 NAND 物理偏移。

`A0484B0C` 同样先读 NAND，再把 `0x354` 字节复制到 `*[A078B604]`；读取页号由 SYS 表 `+8` 与 NAND 几何共同计算。表与 flash 之间是装入/复制关系，而不是 RAM 地址直接映射 NAND。

`A0484CF4` 首先对现有 SYS RAM 表的 `[0,0x1CC)` 计算 CRC，比较 `+0x1CC`，并检查 `+4` 及状态字段。有效时可能直接使用已有表；否则会尝试装入、重建表与 BBT，且存在调用写回函数的分支。`A0483D98` 能依据运行时分区配置重建这两张 RAM 表。因此：

- RAM 表可能由 BLD 预留、NAND 重读或 RTOS 重建，不能仅凭 CRC 推断其生成阶段。
- 表有效不代表与 NAND 当时的表逐字节相同；不能把它当作原始 NAND 备份。
- 调用 `A0484CF4`、更新器、NAND 包装或“重新初始化以取得表”不属于这条只读调查路径。本轮没有调用这些函数。

系统表前三条记录覆盖 `[0xC,0xCC)`，每条 `0x40` 字节；`[0xCC,0x1CC)` 的其余 256 字节尚未全部解释，解析器保留原始十六进制，不将其命名成 OOB、BBT 或第四条记录。USER 表记录覆盖 `[8,0x348)`，末尾两词同样保留原样。

## 下一步的有界输入

下一轮若继续运行期只读调查，应先重新绑定固件、boot ID 和已知 RTOS 指令指纹，再检查上述四个指针词是否与静态值一致。只有一致时，这份候选才支持检查两个固定窗口：

| 窗口 | 虚拟地址范围 | 长度 | 结构要求 |
| --- | --- | --- | --- |
| SYS | `[A0001400,A00015D0)` | 464 字节 | 3 个固定名称，CRC 位于 `+0x1CC` |
| USER | `[A0001800,A0001B54)` | 852 字节 | 13 个固定名称，CRC 位于 `+0x350` |

项目既有其他 RTOS RAM 观测采用 `PA=VA-A0000000`，但这两个低地址窗口本身未被观测。对应 `PA=0x1400/0x1800` 只是候选换算，必须确认运行期映射和读通道适用；不是已经验证可以直接读取的设备命令。指针不符、映射不明、CRC/名称/长度不符或两次快照不稳定时，应记录差异，停止扩展读取范围。

拿到窗口后，应保留原始字节、捕获来源、固件身份、时间及前后两份 SHA，再用解析器检查。USER RAM 表可与既有 `VENDOR_DATA` 表逐字节比较以交叉校验；不同不应自动写回或“修复”。SYS 表中非空记录的 `actual_bytes/data_crc32/load_address` 可以形成**启动分区元数据指纹**，帮助筛选后续公开固件或备份；CRC32 不是强身份认证，匹配也不能证明隐藏内容的 SHA-256 或某个恢复工具兼容。

此步骤仅推进隐藏启动区身份调查。即使成功取得 SYS PTB，P11 的冷启动与独立恢复仍缺少进入条件、握手、坏块/OOB规则、恢复写入和实际恢复闭环，不应升级为“恢复可用”。

结果包含 8 条固定指令核验、4 个指针词、15 个原厂选择器场景、2 个原厂 CRC 函数对照、10 个表损坏负例、1 个固件身份负例、1 个合法空槽正例，以及旧真实 USER 表的 13 条解析控制。损坏负例包括截断、额外字节、CRC 损坏、重算 CRC 后的错误名称和超额实际长度。

CRC 对照实际执行 `A02A79F0` 的原码和本机镜像中的查表常量，输入完全是合成主机 RAM，结果与 zlib/IEEE CRC32 一致。没有执行 NAND、更新器或初始化路径。

未来的本地表文件可通过 `--system-ptb` / `--user-ptb` 输入，要求精确的 464/852 字节；不静默截断，也不接收设备节点。**`--rtos-image` 的 SHA pin 只验证分析代码，无法认证表的采集来源**；输出始终保留 `capture_provenance_authenticated=false`。真实 USER 控制是明确按已知偏移 `[0,0x354)` 从旧逻辑分区中切片，CRC 域完全相同，不是 RAM 转换或新采集。

解析器接受名称正确的空/未使用记录，即 `actual=0`、零 allocation/blocks 或 `FFFFFFFF` 状态；它们不能生成有效内容指纹。实际长度非零时要求存在 allocation/blocks，且实际长度不超 allocation。未知 flag/status 保留原值，不假装已经解释完整表语义。
