# YI 4K 1.10.7：原生代码执行关卡

本报告把“能把文件读入内存”和“能调用一段自定义 ARM 代码”分开。证据来自实体机
`SYS_SW` 的静态窗口与旧样本同体函数比较；没有向相机写内存、执行 payload 或改写
RTOS 分区。

## 已排除的误用

`loadbin` (`0xA02A2584`) 的 1.10.7 控制流是：检查参数 → 解析地址/长度 → 使用
原厂文件 API 读入目标地址 → 关闭文件 → 通过 `r2`/`r6` 调用 Shell 打印回调报告
错误。函数内没有跳转到目标地址、任务创建、I-cache 维护或返回 ABI。真实机版本与
旧样本的差异只有字符串地址的 `movw` 常量；分支和调用目标保持一致。因此：

```text
savebin/loadbin 成功 ≠ payload 已执行
```

## 命令分发表的间接调用

下列两套子命令分发器在实体机 1.10.7 与旧样本逐字节相同：

| 入口 | 作用 | 间接调用来源 | 结论 |
|---|---|---|---|
| `0xA01AB8BC` | `t ants` | 从固定 8 字节表项取 handler，`bx r3` | 只能调用已注册表项；参数只作为 `argc/argv/print` 传递 |
| `0xA0245AF8` | `t ipc` | 从固定 8 字节表项取 handler，`bx r3` | 只能调用已注册 IPC 子命令 |
| `0xA029E098` | 普通 `t` 注册 | 保存名字和 handler 指针，追加链表 | 有原生注册 ABI，但自身不是运行时 loader |
| `0xA029E1A4` | 普通 `t` 分发 | 从注册链取 handler，调用 `handler(argc-1,argv+1,print)` | 需要先让自定义代码进入注册链 |
| `0xA04A8384` | `t drv dma` | 解析 channel/src/dst/size，调用 DMA 搬运 | 具备 D-cache 维护；没有 I-cache、任务创建或跳转 |

这些 `bx/blx` 不是“把用户输入整数当作函数地址”：地址来自固件表或已经注册的
handler 指针。`t app` 中还存在音频/驱动对象的函数表调用，但同样是已有对象的
方法分发，不能直接当作任意地址调用器。

## 当前可复用的执行上下文

RTOS 已有任务包装层 `0xA03BC2BC`，静态参数形态为
`(task, name, priority, entry, arg, stack, stack_bytes, auto_start)`，并向 ThreadX
检查层传入固定对象大小 `0xD8`。这说明自定义任务最终可能复用原厂调度器，但还缺：

- 可安全取得的任务对象/内存池；
- entry 是 A32 还是 Thumb，以及栈对齐和寄存器保存约束；
- 代码和数据写入后的 D-cache clean、I-cache invalidate/同步及多核可见性；
- 任务停止、卸载和异常恢复策略。

`0xA0498728/0xA049878C/0xA04987F0` 只覆盖已观察到的 D-cache 操作，不能把它们
扩展解释为完整的代码执行协议。

补充静态复核：`0xA04A283C(address,size)` 与分析样本逐字节相同，但会改写
CP15 `c9,c0,1`，并在低功耗路径中配合 `0xA04A28D0` 使用。先前把它当作普通
I-cache 同步候选的判断已修正：它更符合指令 cache 锁定/预取路径，不能直接作为
通用代码刷新或多核发布函数复用。精确指令和证据见
[Shell 与缓存报告](device-1107-shell-memory-and-registration.md)。

在实体机 1.10.7 的静态调用索引中，`0xA029E098` 有 22 个直接调用点（13 个调用者），
`0xA03BC2BC` 有 86 个任务创建调用点（79 个调用者）。这说明原厂确实在启动和各个
子系统中大量使用同一注册/任务包装，但这些调用点的参数来自固件初始化对象；调用点
数量本身不能证明存在一个接收 SD 文件路径并创建任意任务的公开入口。

## 下一道最小闭环

下一次原生执行实验应当同时满足：

1. 只使用当前 1.10.7 的 RTOS 哈希和运行期映射；
2. 由已核实的启动上下文创建一次性任务，entry 只写一个固定日志/标记并返回；
3. 在调用前后执行明确的缓存维护，payload 不触碰 EIS、DMA、GUI 或文件服务；
4. 通过 RTOS 原生日志或 Linux `linux_util_svc` 回传进入、返回和错误码；
5. 连续冷启动、空闲、取景和短录像各验证一次，任一异常都能通过移除 SD 文件回退。

在第 1～4 项完成前，不应把 `loadbin`、`t ipc`、`echo_cortex` 或 Linux root 权限
当作任意 RTOS 函数调用入口。

已进一步恢复的原厂任务入口跳板和静态描述符见
[任务跳板分析](device-1107-task-trampoline.md)。已确认这是主控制循环的入口，
描述符第二个字段是发退出消息的回调；替换第一个字段会接管主应用，不适合作为
最初的可返回探针。Attach/Detach 没有提供热替换同步或任务重启协议。

捕获映像的对齐 A32 扫描还找到 10 处指令缓存失效操作，均位于 BOSS 恢复、MMU
初始化或低功耗路径；两处 ICIALLUIS 也不能作为独立函数调用。扫描范围与限制见
[代码发布边界](device-1107-code-publication.md)。下一步优先评估启动期静态扩展补丁的
空间和时序，动态装载路线继续保留首次入口、内存所有权和多核同步三项缺口。

启动期静态扩展现已完成第一轮具体评估：在代码映射页尾找到 3,564 字节填充候选，
对启动调用点制作了 96 字节的离线标记包装，验证分支和整分区内存撤销。没有生成
刷写映像，填充所有权及本机 bootloader/PTB/独立恢复仍需核实；详见
[启动期扩展评估](device-1107-static-boot-extension.md)。

两个真实启动包装 `0xA0188944`、`0xA04B3B94` 及其调用范围见
[任务启动路径](device-1107-task-launch-path.md)。它们证明创建→核心排除→resume 的
可复用顺序，但现有调用点都没有把 entry 变成外部可替换参数。

RPC 注册器 `0xA03CAAB4` 会复制 procedure 表，并由 `0xA03CAE84` 按编号调用
handler。本轮检查的 7 处构造器、26 个回调全由固件常量建立；详见
[RPC 扩展接口](device-1107-rpc-extension-contract.md)。这提供了将来扩展的控制面 ABI，
但没有打通从 Linux/SD 文件到自定义 RTOS entry 的首次执行。

后续[非缓存可执行RAM页表审计](device-1107-noncache-executable-ram.md)确认原厂初始化构造包含Normal NC、XN=0的RAM，且`A2100000..A3100000`由secondary byte pool管理。[分配/释放合同](device-1107-nc-pool-allocation-contract.md)进一步以39次原码合成调用验证受检查分配、对齐和original释放。没有实际运行期页表/独占分配，也没有向外部暴露的完整分配→发布→首次进入入口；这些进展不改变上述执行与恢复关卡。
