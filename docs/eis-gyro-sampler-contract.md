# EIS 采样器与历史环：原码集成边界

2026-11-12。继[驱动输入合同](eis-gyro-input-contract.md)后，本轮把原始 `A03AF31C` 包装器、`A0385780` 采样器的 warmup 分支、`A047EDE4` SPI 驱动、`A048E3F8` 软件 tick 读取及原厂算术 helper 串联执行。13 个场景、18 条固定指令定位通过：[审计程序](../scripts/audit_eis_gyro_sampler_contract.py)、[回执](../artifacts/verification/2026-11-12-eis-gyro-sampler-contract/audit.json)。

所有输入、RAM 和 SPI 故障/延迟均为显式主机模型；没有设备访问、真实中断调度、视频帧更新、warp 生成或 DSP 发布。固定 RTOS SHA256 仍为 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。下述事实不能证明真机采样率、传感器新鲜度或共同视频时间锚。

## 读取与提交顺序

ready 状态下，原指令按以下顺序工作：

1. 通过 `A048E3F8` 从 `A1A3A528` 读取一次软件 tick，存入 `A1702C40`。
2. 保存当前历史索引，再调用 gyro ops `+8`，传入 mode `1`、输出地址 `A1702C30`。
3. 将输出前三个 unsigned16 原值写入历史环；不根据读取返回值决定是否接受。
4. 按调试配置打印，再将本次开始 tick 写入 `A170AB60`。
5. 推进历史索引并按长度回绕，将原值左移 8 位存为 UQ8，更新偏置历史。

原厂驱动读取失败时仍返回 `0`；本轮进一步证明**完整采样器仍把旧值提交到新环槽并推进索引**。debug 字段 21 非零跳过实际读取时，也会提交已有输出并推进索引。调用外层 `A03AF31C` 后无论下层结果如何都以 `mov r0,#0` 返回，不能用外层零返回当作一次有效采集的凭据。

两个 ready 调用都在 tick1000 时，各产生一个样本；下一次跳到 tick1017，只插入一个样本，没有补回中间时刻。样本序号因此不能靠 `初始tick+环索引` 还原。测试只覆盖所选 warmup 分支，不推断实际任务是否会以相同 tick 重入。

启动 ready 标记为零时，原函数先判断 `当前tick−启动tick` 与 descriptor `+22`（十进制100）。tick99 只记录一次 sleep(100)；tick100 执行完整原厂 open 配置并设置 ready，尚未读取样本；下一次 ready 调用才读取。sleep 和 SPI 并未在模型中消耗真实时间，不把参数100解释为实测等待时长。

## 软件 tick 与打印门控

注入 SPI 读取耗时7个软件 tick：开始 tick101，SPI 返回时计数器为108，采样器保存的 tick仍为101，打印时为108。故这是**调用开始的软件时间**，不是 SPI 完成或传感器内部采集时间。

字段22的取模判断读取旧的 `A170AB60`，之后才更新成当前值：

| 上次保存 tick | 本次开始 tick | 模数 | 是否打印本次样本 |
| ---: | ---: | ---: | --- |
| 100 | 101 | 50 | 是；延迟模型中的日志 tick为108 |
| 101 | 150 | 50 | 否 |

这补充了[历史文本日志](device-eis-recording-trace.md)的精确解释：相邻打印常差50 tick，并不能证明某个记录是在可见前缀 tick进行采集，更不能恢复完整高频 IMU 序列。第四输出槽仍未被 mode1 定义。

静态原码另显示：timer 回调 `A03974C4` 设置事件 bit1，主任务检查该 bit后发出 `0x100F`，进入上述采样包装器。事件是通知路径，不能单靠1000的timer配置或事件数量认定每次都取得独立传感器样本。本次没有仿真完整 RTOS event wait、scheduler 或硬件定时器，也没有改变历史1ms设计尺度的证据范围。

## 历史布局与捕获接缝

原始 mode init 的零填充循环处理每通道132个数据 word，随后放5个元数据 word；通道步距为137个 word。**137是步距，不是137个有效样本容量**。X 数据从 `A1702D00` 开始，长度和 next-write索引分别在 `+0x210`、`+0x214`；Y/Z 数据起点为 base加137/274个 word。UQ8数据要先右移8位恢复原始unsigned16，再减32768回到原始signed counts。

本次显式选择合成长度132，验证索引130→131→0→1；不声称这就是当前真机运行长度。mode init 按运行参数计算长度，未来捕获必须读取并核对实际长度，不能把通道步距当容量或盲目复制到相邻元数据。

原始环不提供本次 warmup提交的逐样本时间戳、SPI状态或新鲜度位。采样前后直接拷整个环，还缺少原子快照与并发所有权。未来有限记录器应在受控读取边界记录：

- 运行 epoch、单调调用序号、ready/模式/三轴方向配置身份、环索引。
- SPI调用前后软件 tick、实际SPI返回与传感器状态/时间证据；原厂mode1零返回不足以判定新鲜。
- 原始三个counts、读取配置、溢出/丢失计数；保留软件时间与硬件时间的区别。
- 与曝光/有效帧/编码PTS单独关联的身份，以及记录缓冲的容量、发布和安全回收凭据。

本轮没有安装记录器或创建RTOS任务。既有最小stock进入确认不包含新的gyro采集写入；本页仅把后续记录器的具体接缝和必须保留的数据固定下来。[原生入口、cache与恢复门槛](device-1107-native-execution-prereq-matrix.md)仍保持未完成，候选算法不得据此升级成可部署或已标定。
