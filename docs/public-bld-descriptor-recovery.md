# 公共 BLD：PTB 描述符和启动回退的进一步恢复

对象是公开社区 `v1.10.52` 的 `_part_bld.a9s`，SHA-256 `259ed36093252298186c7e39c5f3400ba307f44224aba467ab885da8e1e5cbd7`，加载基址 `0x10000000`。它只作为 1.10.7 真机 PTB 的结构参考，不能当作真机隐藏 BLD 的逐字节镜像。

## 描述符选择和加载

`0x10002308` 的选择器有两个表：

- `r0 != 0` 时，检查索引 `<= 0x0c`，从 `0x1000cdd8` 指向的表取 `base + index*0x40 + 0x08`；
- `r0 == 0` 时，检查索引 `<= 2`，从 `0x1000cdd4` 指向的表取 `base + index*0x40 + 0x0c`。

`0x10002358` 是分区读取器。它读取全局 NAND 几何中的页大小字段和每块页数，使用描述符 `+0x34` 的实际字节数计算需要读取的页/块，并用 `+0x28` 的块数限制遍历；起始块来自 `+0x2c`。遇到坏块时会通过坏块状态查询跳过，之后把数据复制到调用者给出的加载缓冲区。返回值只表示这一轮读取路径的成功/失败；它没有显示签名验证。

在 `0x10006900` 附近，最终启动路径先调用选择器，再读取所选记录的 `+0x34`。为零则打印 `ActualByteSize = 0, return` 并放弃；非零时使用 `+0x30` 作为加载地址，调用分区读取器，随后从临时上下文取入口并执行 `MOV PC, entry`。

## `+0x38` 的边界

对所有静态内存操作做了逐指令索引，结果见 [bld-descriptor-uses.json](../artifacts/firmware/bld-descriptor-uses.json)。能确认属于 PTB 记录的写入点是 `0x10002724`：扫描失败时同时执行：

```text
record+0x34 = 0
record+0x38 = 0xffffffff
record+0x3c = 0xffffffff
record+0x23 |= 0x40
```

因此 `+0x38` 至少是失败/无效状态的一部分。公开 BLD 的其他 `#0x38` 访问还属于栈或另一个全局控制结构，不能按同一描述符字段解释；这也是简单字符串/偏移搜索会产生误报的原因。正常有效记录中的 `+0x38` 具体语义仍未知。

## 启动计数和三次回退

`0x10006834` 读取一个全局启动状态字节（偏移 `+4`），并多次调用 `0x100027b8`。后者把该字节与 `0xA0000030` 的硬件/启动状态字比较，返回“是否相等”的布尔值。分支会打印以下已定位的消息并选择不同的表/索引组合：

| 地址 | 字符串 | 后续动作 |
|---|---|---|
| `0x100069b0` | `Normal updater boot` | 清理/更新状态后重新走选择器 |
| `0x10006a08` | `Fwupdater err 3 times` | 调整状态并选择另一条记录 |
| `0x10006a28` | `sys boot err 3 times` | 调整状态并选择系统记录 |
| `0x100069d4` | `Normal sys boot` | 选择系统记录 |
| `0x10006a48` | `# Load Kernel` 后的系统初始化 | 读取内核/RTOS参数，最后跳转 |

这些路径表明有“连续失败后切换 updater/system”的回退机制。它们没有证明能绕过 PTB CRC、签名或版本检查，也没有暴露真机隐藏 BLD 的物理位置。

## 对真机二开的影响

1. 已闭合的真机 SYS_SW `actual_size` 和数据 CRC 可以用于验证逻辑分区捕获；替换镜像仍必须满足隐藏 BLD 的完整检查和坏块/OOB规则。
2. 目前最安全的工作仍是离线恢复字段和控制流，以及继续从 Linux/RTOS 获取启动日志；不能仅凭公共 BLD 生成刷写包。
3. 若未来获得真机 BLD 或独立恢复协议，首先应验证描述符选择、装载长度、坏块跳过和回退状态，再设计可回滚的测试镜像。
