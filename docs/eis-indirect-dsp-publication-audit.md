# EIS 发布地址进入 DSP 命令的间接路径

日期：2026-11-10。本轮仅离线读取固定 RTOS 窗口和既有 Ghidra 导出，没有接触真机、执行固件或提交 warp。新结论是：**`0xA0699160` 作为共享发布字的地址，经 `VCAP_SETUP.eis_update_addr` 进入 CPU 侧 DSP 命令缓冲；不需要 CPU 另行读取这个发布字再构造每帧 warp 命令。** DSP 微码是否、何时读取它仍未观察到。

## 指针层级的修正

需要收紧此前 [warp 发布契约](device-1107-eis-warp-publication.md) 末段和 [消费者审计](eis-warp-consumer-audit.md) 中“描述指针写入 `+0x80`”的措辞：固定指令表明，`+0x80` 保存的是**状态槽地址**，槽内的 `+0x24` 才保存 warp 描述地址。两次转换的输入不同：

| 指令位置 | 已确认的赋值 |
|---|---|
| `A02C6068` | `r5 = 0xA06990E0 + index × 0x40`，即当前状态槽 |
| `A02C6178..618C` | 转换 warp 描述地址，写入 `[r5 + 0x24]` |
| `A02C6190` | 跳回 `A02C60C8` |
| `A02C60C8..60DC` | `r0 = r5`；转换状态槽地址，写入 `[r7 + 0x80]`，即 `0xA0699160` |

这一结论来自寄存器数据流与固定字节核对，超过只检查 `str r0, [r7,#0x80]` 能给出的类型信息。它不改变两槽索引回绕的既有观察，也不证明两槽足够覆盖 DSP 最坏延迟。

## 启用时注册共享发布地址

`A02C5FD8` 的启用状态变化分支：

1. `A02C6194` 从固定 literal `A02C61D0` 读出 `0xA0699160`。
2. `A02C61A4` 计算 `r7 = 0xA0699160 - 0x80`，得到两个状态槽的基址。
3. `A02C61A8` 对 **`0xA0699160` 这个发布字的地址**调用 `A04A3B24`。
4. `A02C61BC` 将结果保存到全局 VCAP 对象的 `+0x58`；`A02C61C4` 更新该对象 `+0x28` 的参数；`A02C61C8` 清零发布字。

固定镜像中 `DAT_a06f3380` 初值为 `0xA064F3C0`，其首字初值为 `0x08000001`。这些是镜像初值，不能冒充运行时内存状态。

## 从 VCAP 对象到命令缓冲

`A02C4DBC` 在配置流程中，于 `A02C4F74` 调用 `A02BE570(1, DAT_a06f3380)`。`A02BE570` 的作用有明确的命令标识和字段打印名称：

- `A02BE574..57C` 写入命令码 **`0x08000001`**，字符串名称为 **`VCAP_SETUP`**。
- `A02BE584..58C` 读取并转换对象 `+0x58`，随后将结果写回原字段。该字段的原厂打印字符串为 **`eis_update_addr`**（固定地址 `A05C21C0`）。
- `A02BE5C4..5CC` 传入长度 **`0x80` 字节**，调用 `A02BE4C8`。
- `A02BE4C8` 根据 DSP 工作状态选择命令缓冲上下文，再通过 `DAT_a06f30f8[index]` 间接转发；其中一个状态分支会提前返回，因此不能说每次调用必然入队。
- 固定镜像的分发表第 1 项为 `A02B4858`。它分配下一 `0x80` 字节命令槽、清零槽并调用 `A04F8D24` 复制传入命令。成功返回仍只表示 CPU 侧缓冲操作成功。

```text
VCAP_SETUP +0x58 (eis_update_addr)
    -> 地址转换后的 &publication_word (0xA0699160)
        -> 地址转换后的当前 0x40 状态槽
            -> 槽 +0x24：地址转换后的 warp 描述
                -> 描述 +0x08/+0x0C：水平/垂直 warp 表
```

前述赋值和命令缓冲路径是静态证据；箭头中的 DSP 解引用行为仍是待验证协议。这条地址注册路径解释了之前“5 个固定引用全部位于生产者”并不等于“没有下游路径”。本轮没有重复那 5 个引用扫描。

## 仍然不能推导的事项

`A04A3B24` 先检查固定映射表，再检查运行时映射表；后者初始指针位于窗口外的 `A14453B0`。因此本报告不计算这些共享地址的实际物理地址，也不声称两处重复地址转换对任意输入都幂等。

`A02C61D4` 会读取 VCAP `+0x58`，用 `A04A3BD4` 转回 CPU 地址，再读 `+0x10`、`+0x20..+0x3C`，或者写 `+0x3C`。它确实访问共享发布字后方的字段，但本轮没有发现它解引用当前状态槽指针，不能据此给这些字段命名为 DSP completion、ack 或旧槽释放标志。

本轮审阅了完整导出中引用 `DAT_a06f3380` 的 62 个函数，重点核对生产者、VCAP 配置调用者、命令构造器、间接分发器、CPU 命令缓冲器和共享字段读回助手。负面证据到这些 CPU 路径为止；没有 DSP 微码加载、锁存或帧完成轨迹。CPU clean、命令复制返回成功、模式切换等待均未被当成 warp 锁存确认。

下一步的精确问题是：DSP 消费 `eis_update_addr` 时读取哪几个层级、在哪个帧阶段锁存，何时才允许覆盖旧状态槽和共享描述。找到这条 CPU 命令链不会解除自定义 warp 提交的停止门槛。
