# 相机验收探针的精确模式恢复

`CameraLiveProbe` 临时切换录像、拍照模式时，现在同时保存原始 `system_mode` 和受影响的 `rec_mode` / `capture_mode`。只保存父模式会丢失延时、慢动作、连拍等原始子模式偏好，因此不足以支持“设置已恢复”的结论。

清理顺序为：先恢复所有修改过的子字段，最后通过原始父模式所对应的已恢复子字段重新激活原始模式。不会向原厂可能“应答成功但未生效”的父字段直接发送 setter，也不会通过选择普通录像覆盖原有延时偏好。每次恢复均读回确认，最终选定设置对比也包含两个子字段。

失败恢复的两个 loopback 协议用例位于 `CameraConfigurationTest`：

- 起始为延时录像、非活动拍照偏好为连拍，经过普通录像和单张拍照后，恢复两项子偏好以及原父模式。
- 起始为拍照模式，临时录像子模式写入已应用但应答断链；保存原值的记录仍存在，重连后能恢复慢动作偏好、连拍偏好及拍照父模式。

这两个测试使用明确的本机 TCP 模拟相机，验证请求顺序、实际读取值和不确定写入后的恢复逻辑，不证明实体设备故障恢复已经验收。现有 [真机配置探针 01](device-config-probe-01.md) 只证明普通画质修改、读回和正常恢复；未在相机上注入断线或失败，也没有运行实体 Android 手机 UI。

若恢复遭拒绝、超时或读回不符，探针记录 `cleanup_error` 并失败退出，不把未确认的结果标记为成功。普通 Gradle 单元测试不自动连接相机。
