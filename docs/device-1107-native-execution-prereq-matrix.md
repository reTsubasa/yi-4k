# YI 4K 1.10.7：EIS 最小原生执行前置条件矩阵

更新时间：2026-11-11。对象为本机普通 YI 4K 固件
`Z16V13L_1.10.7_build-20180202122459_git-a8f840ce_r2746`，RTOS 窗口 SHA-256
`eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。

这份矩阵只回答一个问题：在讨论“让一段最小自定义代码进入 RTOS、返回并可恢复”之前，哪些前置条件已经有证据，哪些仍然缺失。它不构成可执行补丁、写入命令或真机执行授权。所有现有证据均来自固定镜像、离线反汇编、Unicorn/主机合成执行或既有只读快照；本轮没有写入相机 RAM、固件、分区或启动区。

## 状态定义

- **已证实**：证据直接覆盖该条件，但只限文档中给出的固件身份、地址范围和测试模型。
- **部分**：有相关静态或主机证据，但缺少运行期、所有权、并发或恢复闭环，不能作为执行许可。
- **缺失**：当前没有足够证据，必须先补齐才能进入下一关。
- **停止**：一旦触发该行的停止条件，立即停止后续写入/执行工作，恢复到只读观测。

## 进入下一关的硬门槛

在任何真机写入或执行前，至少需要把 **P1、P3、P4、P5、P6、P8、P10、P11** 从“缺失/部分”升级为有边界的运行期合同，并完成一份具体方案，包含：

1. 固件指纹、目标地址/池、写入长度、执行核心和 ABI；
2. 写入前后的读回校验、D-cache/I-cache/ISB/跨核顺序及完成回执；
3. 只写固定日志/标记的最小 entry，不读 gyro、不写 warp、不调用 DMA/MMIO、不获取 EIS/视频共享锁；
4. 进入、返回、错误码、超时和任务停止的独立结果通道；
5. 触发禁用方法、冷启动方式、失联处理和可验证的回滚步骤。

其中 **P9** 必须保持为隔离约束：最小探针即使成功，也不能据此进入 EIS 算法替换。只有影子模式、原厂输入输出关联和运行期边界 trace 齐全后，才能讨论单变量替换。

## 用户确认边界

以下事项属于本矩阵的“是”，需要用户在具体方案审阅后单独确认：向相机 RAM/启动区/固件/分区写入；创建或恢复 RTOS 任务；修改命令表、callback、EIS/VCAP/ORC 共享状态；执行可能导致失联、崩溃、无法启动或需要物理恢复的代码。普通主机分析、离线反汇编、只读 API/状态采集、构建和测试不需要额外确认。
