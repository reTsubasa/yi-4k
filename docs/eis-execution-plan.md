# YI 4K 机内 EIS：后续执行计划

目标：录制完成即可使用，优先减少原厂 EIS 引入的果冻、局部拉扯和突然回弹，允许少量自然运动。依据是用户反馈“关 EIS 后基本没有果冻，但画面抖且模糊”；这支持优先检查稳像处理链，尚不能证明某一个 RSC 参数就是根因。

现状（2026-11-10更新）：已定位 ARM 侧采样、逐帧算法、按行补偿、网格和 DSP 提交入口，并完成 [用户1.10.7真机的函数核对](device-1107-eis-validation.md)、[原厂 EIS 有限录像诊断和视频完整解码](device-eis-recording-trace.md)，以及 [RTOS 原生池和任务查询](device-1107-console-and-readiness-validation.md)。**原厂 Shell 命令能执行，不代表自定义 ARM 代码已能执行。** 仍无自定义算法运行、连续无丢样 gyro 遥测或画质改善证据，也没有可直接运行的 loader。全映像自动静态分析不等于完整恢复源码或全部运行协议。

SharePreview 只提供低分辨率分析帧，没有接入录像 EIS/warp 输出。它现在是未来视觉辅助的可选支线，**不作为替换陀螺仪 EIS 的前置条件**，当前不再重试其初始化。预录、语音、安卓控制是另行评估的功能支线，不改变本计划的编码前 EIS 目标。

## 1. 执行顺序与交付

首轮连接和探针的逐步操作见 [真机验证操作](device-validation.md)。

Linux专项补充：社区样本含 `bootcmd.sh` 钩子，本机1.10.7没有对应S99postboot，见 [系统分析](linux-system-analysis.md)。先前 `/dev/mem` 快照没有闭合缓存一致性且相关探针发生过死机，不再把 Linux 轮询 RTOS 私有内存作为下一步。输入契约优先用本机字节静态核对及有界原生观测恢复；新增 RTOS hook/算法补丁仍须通过最小原生执行关卡。

| 阶段 | 执行动作 | 交付与通过条件 |
|---|---|---|
| 0. 对齐实体机，已完成当前样本核对 | 使用本机 1.10.7 RTOS 窗口及函数指纹，不套用社区样本地址含义 | 固件身份和哈希明确；后续固件变化须重新定位 |
| 1. 建立画面对照 | 用户按下节拍 EIS 开/关原片；研究侧检查运动、局部形变、模糊与曝光 | 基线报告；选出稳定复现果冻的模式和运动，区分局部形变、全局抖动与曝光拖影 |
| 2a. 当前静态主线 | 闭合下节 IMU/帧/warp 契约；追踪原厂的 staging→LiveviewEisConfig 发布链 | 地址绑定到本机哈希，明确每字段单位、发布顺序和剩余未知，先不更换网格 |
| 2b. 打通最小原生执行 | 恢复加载/调用路径、内存归属、指令集/ABI、缓存协议与原函数返回；完成可回退的载入方案后真机验证 | 最小探针能够加载、输出版本标记并返回；原厂录像仍正常，卸载或重启恢复原路径 |
| 3. 只读观测 | 原厂有限诊断已完成；下一步在已确认接口记录可逐帧对齐的 IMU、曝光、网格和发布耗时 | 一组可对齐的录像和日志；溢出、丢样、时钟换算均有明确记录，观测本身未引入超时 |
| 4. 单项消融 | 先主机分析，再真机逐项旁路/调参，保留整体稳像并检查按行项、相位和映射 | 证明哪项改变影响果冻；能够复现改善或否定假设，每次只有一项变化 |
| 5. 最小算法替换 | 三轴姿态→保守因果平滑→镜头/逐行投影→原 DSP 网格，逐层启用 | 先在一个原厂支持 EIS 的模式得到机内编码样片，通过画质和实时验收 |
| 6. 扩展与固化 | 验证其他模式、长录、温升、低光和启停，再决定加载方式或固件补丁 | 模式支持表、回退办法、实测限制；最后才制作可复现的发布包 |

阶段 1 画质对照尚未完成；2a/2b 可独立静态推进。2b/3 是可靠修改算法的前置条件，不能用现有 `hello.c` 的编译通过替代。已知池可用约 223.7 MiB 只证明总余量，不证明连续内存、执行权限或可安全分配的算法预算。

2026-11-12 新增[原生证据一致性审计](device-1107-native-evidence-consistency.md)：它交叉核对首入口、TaskQuery 停止保护和自然完成尾部三组离线回执的固定映像 SHA、脚本 SHA、文档链接及 `device_access=false` 标记。审计通过只消除源码/证据漂移，仍不提供设备首入口、I-cache 发布、跨核完成、回收或回滚证据，不能把 2b 升级为真机完成。

## 2. 用户先准备的素材

先用相机菜单中**确实允许 EIS 的一个分辨率/帧率模式**，保持视角、畸变校正和安装方式一致。在明亮环境拍下表，每条约 10–15 秒；每项分别拍 EIS 开、关，运动尽量一致。原片保留，不经聊天软件压缩或二次导出。

| 场景 | 拍法 | 主要观察 |
|---|---|---|
| 静止 | 面向有门框/窗框等直线的场景 | 静态漂移、边缘游动、网格呼吸 |
| 缓慢摇镜 | 以远景为主，匀速左右转动后停止 | 主动运动是否被锁住、回弹和裁切变化 |
| 小幅快速摆动 | 对准同一组直线，小角度左右摆动 | 按行扭曲、相位错误和补偿方向 |
| 步行 | 同一路线，包含远景和近景 | 局部拉扯、视差、残余抖动和实际观看感受 |

优先在可控条件固定曝光；如果当前模式不能锁定，则记录菜单设置与光照，不把不同自动曝光结果当成算法的直接对照。下一轮再增加较短/较长曝光组合，区分模糊和几何形变。不必为首轮购买测试设备。

素材旁记录：固件版本、分辨率/fps、EIS、FOV/畸变校正、曝光设置、场景、文件名、主观最难受的时间点。手持开/关不是严格相同运动，首轮用于定位现象；定量改善需要重复录制和日志佐证。

## 3. 研究侧紧接着恢复的接口

本节地址已以用户本机 `Z16V13L_1.10.7_build-20180202122459_git-a8f840ce_r2746` 对齐。当前保留的 RTOS 窗口为 `artifacts/device/2026-11-09-linux/rtos-analysis/rtos-window.bin`，基址 `0xA0100000`，SHA-256 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。旧社区 v1.10.52 的分区哈希不作为真机写入依据。

1. **最小执行通道**：从已有 Shell/命令注册证据恢复调用条件；明确谁分配可执行内存、如何跳转、如何返回、何时刷新缓存。`loadbin` 本身只加载字节，不承担分配和执行。
2. **输入数据契约**：沿 gyro read `0xA047EDE4` 与采样主体 `0xA0385780` 恢复轴向、量纲、偏置、采样频率与时戳；沿模式初始化 `0xA037FE20` 恢复 RowTime、sensor 模式及裁切关系。已确认三轴各 132 槽、写指针推进和 SOF/EOF/采样事件顺序，详见 [环形区与帧事件契约](rtos-ring-and-frame-contract.md)。原厂日志 tick 的设计单位已由本机定时器/指令链收紧为 1 ms，仍不等于硬件采样时间或曝光中心，见 [录像时序证据](device-eis-recording-trace.md)。
3. **逐帧输出契约**：沿 `0xA0392CB0`、`0xA038EA48` 和 `0xA0312460` 恢复网格尺寸、定点精度、映射方向、目标帧、表生命周期及 DSP 提交截止时间。新核对表明 EIS 使用 selector `0xF` 仅准备并 clean warp 表，再通过 `0xA02C5FD8` 的双槽状态块发布；不能用一次独立 SetWarp 返回成功替代完整时序，见 [warp 发布契约](device-1107-eis-warp-publication.md)。
4. **可疑形变项**：恢复按行函数 `0xA0391CF0` 和调试分发 `0xA0394CC0` 的参数调用协议，核实相位、RscScale、运行分支与其他校正项之间的关系。

每项都保留“静态证据、推断、待真机验证”状态。调试子编号不等于已确认的 Shell 命令；镜像初值不等于录制时运行值。

紧接着的具体交付是：恢复 `0xA02C5FD8` 发布后的 DSP 消费/锁存时机，以及 `0xA03119A8 → 0xA032CF38` 生成的两平面表格式。只有闭合表的精度、pitch、所有权和帧相位，才设计保持原表内容不变的观测 hook；第一份自定义表先在主机验证，再进入真机消融。

## 4. 只读记录的最低内容

下面是待实现的观测协议要求，当前没有声称已经能采到这些数据。

- 会话头：固件 RTOS 哈希、模式/裁切、镜头校准标识、时钟频率与回绕规则、单位/轴向转换版本。
- IMU：序号、采样/接收时戳及其语义、原始三轴数据、偏置和状态；区分传感器采样时间与软件读出时间。
- 帧：帧序号、SOF/EOF 回调时间、曝光与行读出时间；实际硬件时间含义需校准。
- Warp：目标帧、表标识/尺寸/格式、原始表快照、算法开始/结束和提交时间、状态码。
- 完整性：丢样、覆盖、日志丢弃和表未就绪计数。

实时路径只写有界内存缓冲，由低优先级任务批量落盘；缓冲满时明确计数，避免阻塞 EIS。高频日志不能直接同步写卡。观测前后都比较原厂超时、丢帧与画面，检查探针是否扰动结果。

## 5. 消融与替换的实验顺序

| 实验 | 只改变什么 | 回答的问题 |
|---|---|---|
| A 原厂基线 | 不改变算法，记录真实运行参数 | 问题出现时实际启用了哪些路径？ |
| B 按行项消融 | 在确认合成关系后，仅旁路可疑按行增量，保留整体稳像和必要镜头校正 | 果冻是否随该项显著变化？其他 RSC 路径仍需检查 |
| C 时序/比例校准 | 每次仅调整一个已确认单位的相位或比例，先用回放选范围 | 是补偿时刻、方向或幅度错误，还是模型本身不足？ |
| D 全局几何替换 | 三轴四元数与保守因果轨迹；镜头、裁切和 DSP 输出契约保持可控 | 整体稳像能否减少回弹和几何不一致？ |
| E 逐行三维补偿 | 在 D 基础上加入源行曝光时刻的三维投影 | 校准后的 RSC 能否进一步降低行间残差而不引入游动？ |
| F 模糊感知策略 | 对长曝光/大角速度降低不合理锁定，协同曝光与裁切 | 能否减轻“画面位置稳、内部拖影跳动”的观感？ |

不能直接把合成 warp 表整体清零来代替实验 B：表中可能还有镜头、窗口和其他必要变换。每次修改应有退出/恢复条件，并保存配置与日志。

主机回放用于检查时序、几何与候选算法，是开发步骤；最终验收必须是相机直接编码出的文件。未取得编码前帧或明确视频几何关系时，不能声称已精确复现原厂像素处理。改动后不能只看主观“更稳”：应分别记录全局运动和局部形变。

## 6. 第一版验收

- **观看效果**：相同场景重复测试，直线局部弯曲、边缘游动和突然回弹降低；残余全局抖动、裁切和清晰度分别记录。允许少量自然运动。
- **几何**：镜头/模式一致时比较行间残余运动和直线形变；排除近景平移视差，不能用纯旋转模型承诺解决所有局部运动。
- **边界**：无黑边、网格折叠、越界和突然变焦；检查整个非线性边界而非只看四角。
- **实时性**：记录 p50/p99/最大耗时、提交余量与漏期数。以实测 DSP 截止时间为准，30 fps 的 33.3 ms 并不等于全部算法预算。
- **系统行为**：覆盖录像启停、模式切换和长录，检查丢帧、音画同步、温升及状态恢复。

第一版的明确目标是：**一个已验证模式中，比原厂少果冻，保留有效稳像，直接得到正常编码视频**。水平锁定、未来帧优化、视觉辅助和全模式支持后续再评估。EIS 不能恢复曝光过程中已经丢失的细节，因此“抖得模糊”还需独立核实曝光因素。
