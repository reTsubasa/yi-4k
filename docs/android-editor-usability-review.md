# 剪辑流程 review 与修复

2026-11-11。本轮围绕“选片 → 预览选段 → 裁剪 → 导出 → 打开成片”检查现有本地剪辑，没有改变相机或原视频。

| 原问题 | 已落实的行为 |
| --- | --- |
| 选片入口在长页面底部，空态不容易开始 | 选片入口移至预览上方；导入后显示“更换视频”，同时保留原文件名 |
| 缩略图时间轴只能看，无法拖动 | 时间轴支持左右双柄拖动，自动选择最近的边缘；起止滑条继续提供精确、无障碍调整，两种控制实时同步 |
| 拖动可能让起止点交叉 | 共用 source-time 边界函数，保持至少 0.1 秒，起止柄不互换 |
| 缺少显式的选段播放入口 | “播放片段/暂停预览”控制真实 ExoPlayer；播放器使用与导出相同的 clipping、旋转和黑白效果，只循环所选片段 |
| 静音等工具状态不明显 | 活动效果为石墨色实底/白字，非活动为白卡/深字；静音只改变播放器音量，不销毁重建解码器 |
| 导入大文件只能等待 | 新增“取消读取”，关闭本次导入流，未完成缓存由原有导入清理路径删除；已有剪辑源保留 |
| 完成时突然出现原生弹框 | 改为页面内完成卡片，提供“查看视频/继续剪辑”，保留手机相册实际保存路径信息 |
| 播放器释放过程中旧回调可更新新状态 | 回调核对实际 player 身份，释放前先解除活动引用 |
| 编辑页颜色与主页面不一致 | 使用共享 AppPalette：象牙暖白 `#F4EFE7`、陶土橙 `#C4622D`、serif 标题和细线分隔；导出、播放、滑条、选中工具均用橙色 |

保留实际 Transformer 导出、原声开关、90°旋转、黑白、重置、进度、取消、MediaStore pending 发布及生命周期中止清理。未用假视频或进度替代真实编解码。

新增主机验证覆盖双柄拖动/越界、源时间映射、工具选中态与取消导入流所有权。实际 Android workflow 增加“播放所选片段 → 首帧出现 → 暂停 → 效果 → 导出”的步骤，以及页面内完成卡片；原有时长、静音、旋转、灰度、可解码与原片保留断言不变。具体是否通过以父任务最终构建和设备验收记录为准，本文件不预写通过结果。

仍有限制：本轮仍为单视频裁剪，没有多轨拼接、配乐或转场；预览旋转/黑白及改变裁剪范围时仍会重建播放器，以使用真实 Media3 clipping/effects。导出进入后台会取消，可回到页面重试。真实手机 4K/高帧率编解码兼容性和长片导入耗时仍需手动测试。

## 同主题原片回放

`CameraMediaViewer` 同步使用象牙暖白页面、serif“回放/原片信息”标题、陶土橙播放按钮/进度/收藏状态。文件元数据改为暖色细线列表，收藏收进“原片信息”标题右侧，减少整页实心按钮。状态说明使用低对比小字，不覆盖真实媒体。

回放仍只显示实际读取的文件名、大小、分辨率、时长和临时缓存位置；没有增加虚构 EXIF、删除或未实现分享入口。保留绑定相机 Wi-Fi 的读取、取消/重试、真实本地 VideoView 播放、拖动进度、收藏持久化、返回后清理与生命周期释放。视频区域仍使用深色底作为正常黑边显示；这不承担 UI 强调色。
