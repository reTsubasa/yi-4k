# YI 4K 1.10.7：启动期静态扩展评估

## 当前判断

**已找到具体的代码空间候选和启动调用点，并做成可复现的离线标记原型。**
在不扩大当前映像、不移动原有数据、不替换主控制任务的前提下，可以设计一个很小的
启动包装函数。当前仍未证明这块空间在运行期完全无主，也未验证独立恢复通道，因而
本轮交付的是补丁跨度及证据，不是可刷写固件。

本轮没有连接相机，没有修改设备文件、配置或分区，没有执行自定义 RTOS 代码。

| 问题 | 本轮结果 |
|---|---|
| 能否定位容纳最小入口的空间？ | 可以，代码映射页尾有 3,564 字节全零填充候选 |
| 能否明确首次控制流？ | 可以，把启动尾部一条 BL 指向包装函数，再调用原初始化并返回 |
| 是否需要扩大 SYS_SW/改 BSS？ | 这个标记原型不需要 |
| 能否复用原厂分配池建立独立任务？ | 已核对池建立早于候选点；任务资源/失败路径有可实施设计，尚未实装 |
| 原型能否离线装配和撤销？ | ARM 装配、分支解码、4 组 ABI 模型检查、整分区内存撤销均通过 |
| 是否能移除 SD 卡恢复原厂固件？ | 不能；写入 flash 的补丁仍会存在 |
| 启动坏了是否能独立恢复？ | 未建立；当前是刷机前最重要的未完成项 |

## 空间：代码段页尾，而非映像末尾空洞

实体机字节核对了 MMU 布局初始化器 `0xA0295CF8`。其代码结束来源常量为
`0xA064E214`，向上取整后的代码映射截止于 `0xA064F000`。

```text
A0100000 ........ A064E214 | 全零候选填充 | A064F000 ........
                           A064E220
                           原型入口，96 字节
```

`[0xA064E214, 0xA064F000)` 共 **3,564 字节**全部为零。
选择 16 字节对齐的 `0xA064E220` 后剩余容量为 3,552 字节；原型末端为
`0xA064E280`。该区已在当前捕获的连续装载数据内，距离映像末尾很远。

与之不同，`0xA0824F68` 后面的空洞不能作为扩展空间：

- 主启动函数使用 `0xA0828000`、`0xA0828400` 作为串口配置缓冲。
- 启动向量区保存多份位于 `0xA0ACxxxx..0xA0ADxxxx` 的栈指针。
- MMU 代码使用 `0xA0B98000` 的页表区域。
- BSS 清零从 `0xA0FB3000` 开始，终止于 `0xA1A5117C`。

这些地址说明“文件末尾到 BSS 之间”包含未存于文件的运行期资源；32 MiB NAND
分区的剩余 FF 字节也不能证明对应 RAM 会被加载、可执行或可独占。

### 引用与权限核对

对公开旧样本和本机两份 Ghidra 索引分别扫描 428,243 / 438,936 条引用，没有发现
指向填充候选区的内存引用；两份函数索引也没有与之相交的函数体。对实体机整个窗口
逐个 4 字节对齐原始字扫描，没有发现指向该区的数值/带 Thumb bit 的指针。

**这些是有范围的否定结果。** 未覆盖所有指令物化地址、未对齐数据、间接计算或
运行期 DMA/写入，也未确认校验机制不会覆盖填充区，不能把它升级成安全空间证明。

代码映射使用的 packed attributes 为 `0x1060F`，它不是硬件页表项本身。按照
`0xA04A3FB0` 的小页构造分支重建，其低属性位为 `0x43E`，候选页基址对应物理
`0x0064E000`，XN=0；该页位于原代码映射内，后续映射从下一页开始。
因此有静态依据认为它可执行，但本轮没有读取实际运行页表或验证权限。

## 插入点：保留原初始化和返回路径

候选点是 `0xA0187BF4` 的 `BL 0xA0186EE8`，位于主启动函数尾部。
原流程在 Host Control Manager 创建之后执行：

```text
if startup_shell_flag == 0:
    A0187BF0: BL A0186E3C    // 启动原厂 Shell
    A0187BF4: BL A0186EE8    // 注册测试/休眠等命令
    A0187BF8: MOV r3, 1
    A0187BFC: STRB r3, [r4]
return
```

原型把第二条 BL 转入 `0xA064E220`：

```text
保存 r4/LR，栈增加 8 字节
调用原 A0186EE8 一次
把原返回值 r0 保存到 r4
用 A02A70EC 打印固定标记
恢复原 r0、r4、返回地址
回到 A0187BF8
```

标记文本是 `[yi4k-ext] stock init returned; wrapper reached`。
它只能表明原初始化返回后到达打印调用；不能单凭此标记证明包装函数最终返回或
整个相机稳定。后续还需结合 API 就绪、取景、录像和第二轮启动验证。

| 修改跨度 | 文件偏移 | 长度 | 原字节/处理 |
|---|---|---:|---|
| 启动 BL | `0x87BF4` | 4 | `bbfcffeb` → `891913eb` |
| 原型片段 | `0x54E220` | 96 | 零填充 → 汇编代码、固定字符串和对齐 |

原型含 44 字节指令；96 字节跨度中部分字节仍为零，两个跨度总共改变 **93 个字节**。
分支目标由 Capstone 解码核对。脚本在内存中的完整分区应用两个跨度，再撤销，结果
与原 32 MiB 分区逐字节相同；这是离线可撤销性，不是 NAND 恢复实验。

ABI 模型使用真实装配指令，模拟两个遵守 AAPCS 但破坏 caller-saved 寄存器的原厂
callee，覆盖 4 种原返回值。验证了原函数调用一次、callee-saved 寄存器保持、调用时
栈 8 字节对齐、原 r0 保留、返回地址和 SP 正确。这不是 CPU 仿真、原厂函数执行或
缓存/调度验证。该插入点不依赖原调用返回的 flags，下一条会重写 r3。

此调用受原厂初始化 flag 控制，不保证每次休眠恢复都会经过。现有 Linux 启动脚本
确有 hibernation 流程，BOSS 恢复也会恢复系统状态；后续必须区分冷启动与恢复启动。

## 独立任务的下一阶段设计

本轮标记原型没有创建任务。它首先验证自定义代码能进入、复用一次服务并返回。
若该阶段通过，空间足够继续放入小型任务 launcher；大算法不应塞进这几 KiB 的填充。

候选点之前，`0xA018756C` 已建立原厂 byte pool `0xA0FD7114`，并将其传给原厂
分配服务。很多本机初始化缓冲也从该池取得，故扩展数据可以研究同池分配，而不是
在原 BSS/栈中挑空白地址。

建议下一阶段一次分配独立存储：TCB 至少 `0xD8` 字节，context，向上对齐的 8 KiB
栈和必要对齐余量。使用 `0xA03BC6DC(pool, &ptr, bytes, timeout=0)`，不等待内存。
池创建和分配 ABI 已用同体函数哈希核对；当前可用量、返回地址和运行期所有权尚未实测。

顺序应为：

1. 分配失败就记录并返回原启动流程，避免启动阻塞。
2. 用 `TaskCreate(auto_start=0)`，检查返回值。
3. 创建成功后设核心排除，检查返回值，再 Resume，检查返回值。
4. entry 只写 context 的进入/完成标记并返回；初版不读 gyro、不写 EIS 网格。
5. context、name、TCB 和栈在任务存活期间必须保持；entry 返回也不会自动删除任务。

失败处理需要按生命周期区分：Create 失败可释放独立分配；核心配置失败且尚未 Resume
时先删除已创建任务，删除成功后再释放。Resume 失败不应不加判断就释放栈；运行状态
必须核实。任务启动后不能由启动包装函数立刻释放资源。初版允许有上限的一次常驻
分配，比让任务自己释放栈更适合验证，但重复启动/休眠时还需 once 状态与回收设计。

## 装载、校验与恢复：目前没有闭环

后续已捕获本机 SYS_SW、VENDOR_DATA 逻辑内容及其中的用户 PTB，并可重算用户表和
SYS_SW 数据 CRC；仍无本机隐藏 BST/BLD/FW_UP、另一张 SYS PTB、物理 NAND/OOB
和独立启动/救援链证据。详见[装载长度与 CRC 边界](device-1107-boot-loader-crc-boundary.md)。
公共 1.10.52 社区整包不是本机 1.10.7 原版升级包。
因此本轮没有把本机 SYS_SW 塞入另一版本的整包。

公共打包器可以重建 CRC，但这是已测样本容器层能力，不证明本机 bootloader 的
装载长度、存储 CRC、升级校验、休眠镜像和修改后启动全部兼容。保持长度只能减少
变量，不能免除这些核对。SYS_SW 裸逻辑分区也缺少 NAND OOB/坏块和必要的启动元数据，
不能当作完整救砖备份。

已定位 `0xA0190B0C`、`0xA029998C`、`0xA029940C` 的 `firmware_force.bin`/普通
升级处理：它们处于当前 RTOS 的文件服务和升级控制路径中。这证明 RTOS 正常时
存在升级入口，**没有证明 RTOS 在候选补丁前卡死时还能从这个入口恢复**。完整升级
校验范围和强制标记语义仍未恢复，不能把 force 文件名当作任意跳过校验的承诺。

下一轮优先获取/核对本机 bootloader 与分区表的只读证据，确认实际装载长度、CRC
存储位置和独立恢复路径，同时继续排除填充区的运行期写入。满足这些条件后才有依据
把当前可审阅的离线跨度组合成面向本机的真机验证产物。
