# 1.10.7 预录时间戳换算补充审计

2026-11-10。对现有 Ghidra 导出和固定 RTOS 镜像继续离线审计，新增 24 个原始 ARM 指令核对、10 个换算前缀模拟用例及 3 个无符号除法用例，全部通过。结果记录在 `artifacts/device/2026-11-10-prerecord/timebase-audit.json`。本次没有建立 REA 会话，没有连接相机、在相机上执行代码、写入设备或修改固件；模拟仅在宿主 Unicorn 内存中运行。

## 本轮结论

描述符的原始 u64 PTS 不能直接作为 MP4 时间戳。`AmpFormat_ConvertPTS` 先减去轨道原点及经换算的偏移，再换算比例，按帧周期的分量进行最近邻量化，最后检查与轨道时序是否一致。量化结果写回轨道不等于函数最终接受该帧：后续同步分支仍可返回失败。

本轮恢复了算术关系及同步条件，但没有确定生产模式的源时钟单位、epoch、所有轨道配置或完整 DTS 推进规则。报告中的 90,000、1,000,000 等值是人为构造的离线测试参数，不能当作真机时钟测量结果。

现有 `docs/prerecord-output-contract.md` 把 8192 个 32 字节描述符写成“约 64 KiB”，应更正为 **262,144 字节，即每个描述符队列 256 KiB**。这不包括编码 payload、控制结构或分配器开销；独立音视频队列各占一份描述符存储。

## 算术关系

以下偏移属于传入的轨道对象；字段名是便于表达的局部符号，不宣称恢复了完整 C 结构体。

| 符号 | 偏移和宽度 | 本轮证据 |
|---|---|---|
| `R` | 描述符 `+0x08`，u64 | 原始 PTS |
| `D` | 轨道 `+0x04`，u32 | 换算目标比例 |
| `T` | `+0x0c`，u32 | 日志称 `TimePerFrame` |
| `S` | `+0x40`，u32 | 换算输入比例 |
| `A` | `+0x58`，u64 | 从原始 PTS 减去的轨道原点 |
| `B` | `+0x68`，64 位模式 | 换算后从原始 PTS 减去的偏移 |
| `F` | `+0x7f`，u8 | 日志称 VFR factor |
| `M` | `+0x7d`，u8 | 值为 2 时加倍量化步长；具体模式名未定 |
| `P` | `+0x60`，u64 | 写回的量化结果 |

在非零除数、`T % F == 0`、`F <= 16` 的有效输入域中，主干等价于：

```text
Q = (T / F) * (M == 2 ? 2 : 1)       // 此处按实际 u32 指令宽度
O = udiv64(mul64(S, B), D)
X = udiv64(mul64(sub64(sub64(R, A), O), D), S)
P = mul64(udiv64(add64(X, Q >> 1), Q), Q)
```

`mul64/sub64/add64` 均按 `2^64` 回绕；除法是无符号整数除法。不能擅自把 `B` 改解释为数学上的有符号偏移后在任意精度整数域化简整个公式。`Q` 的加倍和后续帧步长乘法也可能按 u32 回绕，正常配置值域仍需从配置写入者确认。

原始字节定位：`A03E5B64` 读取描述符 PTS；`A03E5C20/A03E5C58` 用 `UMULL/MLA` 形成 `S*B` 的低 64 位；`A03E5C44/A03E5C48` 减原点；`A03E5C64` 除以 `D`；`A03E5C6C/A03E5C70` 减该偏移；`A03E5C7C/A03E5C80/A03E5C84` 乘 `D` 再除 `S`；`A03E5C94/A03E5C98` 加半个量化单位；`A03E5CA4/A03E5CA8/A03E5CB4` 除并乘回步长；`A03E5CBC` 写回结果。对应伪代码 `a03e5b5c.c:84–127`。

无符号性不只依赖 Ghidra 类型：除法主体 `A05081B2–A05081BE` 比较高低字后用 `BCC` 分支，无符号长除法后续同样使用 carry/borrow；宿主直接运行 `0x8000000000000010 / 3`、`UINT64_MAX / 90000` 等用例，商与无符号结果一致。

## 初始化及同步限制

`a03e5ab8.c:30–39`、原始指令 `A03E5AF4–A03E5B30` 显示：当轨道 `+0x7e == 0` 时，将 `z = low32(T * (u16(+0x78) - 1))` 的 64 位取负模式存入 `+0x68`，并将 `+0x58`、`+0x60` 及 `+0x48` 清零。`+0x7e != 0` 时保留已有偏移。特别是计数大于 1 时，初始化可能产生高位全 1 的偏移，不能一概假定 `B == 0`。初始化清零不等于整个生命周期的原点一直为零，其后写入者仍未完成审计。

同步读取计数 `N=u16(track+0x78)`、轨道 `+0x20` 和 `+0x50`。日志包含 `track->DTS`，支持将 `+0x20` 暂称 DTS 状态；这还不是完整 DTS 生命周期的证明。

- `N == 1`：在 `A03E5EAC–A03E5EC8` 仅用低 32 位计算 `delta = low32(track[+0x50] - track[+0x20] + P)`，零则直接成功。这条分支不是完整 64 位相等检查。非零时要求有符号 `delta` 的绝对值能整除当前量化单位；可调整 `T`、`F` 以及 `+0x20/+0x28`，也可失败。`M == 2` 时还要求绝对差为偶数，再按有符号除 2 调整帧周期（`A03E5FA8–A03E5FC0`）。
- `N != 1` 且描述符 `type == 4`：要求完整 64 位 `P == track[+0x20] - track[+0x50] - step`。证据 `A03E5E6C–A03E5E8C`。类型 4 的实际编码帧名称仍保持未知。
- `N != 1` 且类型不是 4：要求 `P == track[+0x20] - track[+0x50] + low32((N-1)*step)`，完整比较高低字（`A03E5CDC–A03E5D04`）。其中 `step=T`，`M==2` 时为 `low32(2*T)`。

以上路径可能返回 `UINT64_MAX`。换算函数本身还存在断言失败后关中断并原地循环的路径；不能把已定位地址当作可直接在任意上下文调用的 ABI。

## 视频 mux 如何消费结果

`a042ce28.c:114–129` 和 `A042CF2C–A042CF48` 显示：换算返回 `UINT64_MAX` 时，视频写入函数返回 `0xfffffffd`，不会继续写入 H.264 payload。

计数大于 1 时，`A042CF6C–A042CFD4` 还构造类型 4 的时间元数据项：先以低 32 位形成 `track[+0x18] + T - track[+0x20] + low32(P)`，再除以 `udiv32(track[+0x04], track[+0x08])`，乘 mux 对象 `+0x34c`，通过 `A0411E88` 写入。该关系支持后续继续追踪 composition 时间信息，但未据此把元数据项直接命名为某个 MP4 box 或完整 PTS-DTS 公式。

帧周期改变等路径还会写类型 6 项（`a042ce28.c:131–149`）；最终 payload 写入继续使用描述符地址 `+0x14` 和长度 `+0x18`。因此预录适配器仅保存 payload 和原始 PTS，仍不足以无条件复现原生 mux 的时间元数据。
