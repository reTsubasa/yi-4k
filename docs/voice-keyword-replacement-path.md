# 原厂语音口令复用、自定义短语与预录接入

日期：2026-11-12。固定 1.10.7 RTOS SHA-256 为 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。本轮只读归档并执行主机容器检查，没有连接相机、写模型、启用语音或运行声音识别。

**如果目标是让原厂已经能识别的“开始录像”动作保存最近一分钟，无须更换关键词。** 两语言选择各自模型，但共用开始/停止结果映射；可在原厂 START 身份还明确时接入预录状态机。若目标是改成一个原厂不认识的新短语，则需要修改或替换识别模型，改 UI 或日志字符串无效。这里的“无须更换”是接入设计，不表示相机侧适配器和预录后端已安装。

## 三种数据不能混用

| 数据层 | 固定构建中的证据 | 改动的实际含义 |
| --- | --- | --- |
| GUI 和提示内容 | quick setup 的 group `0x1A`、object `0x15E`，descriptor `A06BD194`；点击 `A0138F84 → A016AD30` | 改开关、标签或位图，不能训练一个新口令 |
| 命令语义名称 | PCM 文件名表 `A056E2C8`，语言后缀表 `A056E3F4`，包含 `Yi_action_begin_recording` 及 `_en/_zh` | 命名采样文件和描述识别结果，不是文本词典 |
| 声学模型 | `A04CACD0` 根据语言选择两阶段 graph/float32 weights，构造入口 `A04CAA78` | 决定从声音特征到类别的行为，需要模型数据与前后处理匹配 |

英文日志 “Yi action begin recording” 也属于语义命名。现有二进制权重中没有可直接编辑的中文/英文命令短语表。没有文字命中不代表模型不认识该声音；有日志文字也不代表它接受相同的裸短语。此前未做声学实测，不能由这些归档确认是否须唤醒前缀、是否接受同义词或允许省略词。用户在原厂界面已实际识别成功的读法可以直接复用，不需要为了接预录先改变它。

## 两语言汇入同一 typed action

`A04CA540` 的类别后处理、`A04CB57C` 的公开结果和 `A01B18E0` 的任务消息已由既有原始 ARM 离线场景恢复；类别表位于 `A07E3C14`，五项为 `[1002,1001,1004,1003,1005]`。本轮重新核对固定镜像表和 16 个语义函数指纹，并复核两语言的开始/停止测试记录。

| 语义 | 模型原始类别 | 引擎结果 | 早期消息 | 纯 C 路由输入 |
| --- | ---: | ---: | --- | --- |
| START | 3 | 1003 | `F0010338` | `YI4K_CAPTURE_START` |
| STOP | 2 | 1004 | `F0010339` | `YI4K_CAPTURE_STOP` |

这两个公共结果不再带语言差异，因此预录动作层无需按中文/英文各写一套。现有 [yi4k_capture_trigger.c](../sdk/yi4k_capture_trigger.c) 已有这两种命名空间的显式解码；源码仍与既有 host/ARM 各 13068 项断言通过时的文件哈希一致，本轮没有把历史执行写成新执行。

建议的消息接入位置是主分派 `A019EF90 → A01B22E0` 的开始 handler 之前、且在原厂适用的 app/锁屏/能力过滤之后，以同一个 owner 线程投递 typed START。还必须早于普通 ready gate 和共享 `F001033B → E001000C` 按钮事件的合并：

- 后台持续编码的预录可能使 `A011F260()` ready 为假，原厂开始 handler 会拒绝。
- 越过 gate 注入共享 `E001000C` 又会进入 toggle，可能把后台录制停掉。
- PREBUFFERING 收到 START 应只固定一次最近一分钟，COMMITTING/RECORDING 的重复 START 幂等；STOP 始终保留独立方向。
- 只有预录后端已就绪且本次输入确实被接管时才消费消息；未接管时原载荷交回原厂一次。

这是 [触发路由合同](camera-capture-trigger-router.md) 与 [快门接入合同](camera-shutter-integration-contract.md) 所限定的接缝，尚无上机 hook。START 的触发时间也必须与视频/音频同一采集时钟，不能把原厂 32 位排队 tick 直接标成 64 位微秒。

## 自定义短语：模型格式现在可证明什么

| 语言 | 阶段 graph 地址 / 长度 | weights 地址 / 长度 | 权重容器版本 |
| --- | --- | --- | --- |
| en | `A0790C60` / 4706 | `A0791EC8` / 48928 | `J11_vad_model_en` |
| en | `A079DDF0` / 5053 | `A079F1B4` / 111239 | `H2_classification_model_en` |
| zh | `A07BA43C` / 4706 | `A07BB6A8` / 48924 | `ze_oov_vad_3` |
| zh | `A07C75C8` / 5053 | `A07C8988` / 111237 | `J11_classification_model` |

语言编号为 en=`0`、zh=`1`。两语言各阶段的 graph 字节相同、tensor 名称与 shape 相同，权重数值不同。第一阶段 graph 是 `AudioNIN,100,1,13`，权重 51 项；第二阶段是 `AudioNIN,198,1,13`，权重 67 项，最终 weight `[16,10]`、bias `[10]`。总计四份权重容器、236 项张量。10 维输出仍只有前五类能映射动作，后五类不应擅自分配为新增命令。

嵌入资源经过原厂滚动 XOR 变换，初始 seed=`3FBB720F`：每 word `decoded=encoded XOR seed`，再 `seed=(decoded-seed) mod 2^32`。原始 ARM 变换已有八资源逐字节一致的离线回执；本轮新增主机逆变换，八资源重新编码全部与固定镜像原字节一致，只在内存计算，没有输出替换模型。

权重容器依次是 tensor 数量、`layer:kind:`、rank、shape、little-endian float32 数据，最后为 `version:`、版本长度及版本字符串。新 [预检脚本](../scripts/audit_voice_keyword_replacement.py) 额外检查边界、维度、重复名称、所有 float 有限、版本长度和无多余字节，并将 tensor 来源名称与 graph 对齐。

在一份权重里仅修改一个有限 float，保持 shape 后，主机解析与可逆变换仍通过。这证明**该 XOR 变换本身不提供内容认证**，不证明原厂接受这个修改。截断、尾随字节、零 tensor 数量和 NaN 四个负例由主机预检拒绝；没有据此声称原厂解析器也具有相同校验。

## 加载、校验与推理尚缺的门槛

原始构造路径使用 `A04CACD0` 选择的嵌入地址和长度，而非传入文本关键词或 SD 文件路径。正常语言切换 `A01B2C30` 会暂停、等 idle、释放旧引擎、初始化新模型并清空 FIFO。训练采样 GUI 保存 PCM 不等于把样本训练/写回模型；现有证据没有这样的回写链。

原始资源/解析边界是 graph 变换 `A04F0048`，权重变换 `A04E839C → A04E81A4`；现有 ARM 资源审计在解析器或构造入口处用了明确替身，没有执行完整解析/推理。不能从主机读取成功推导原厂内存分配、tensor 重排、运算顺序、数值精度或网络推理可用。两阶段阈值和第一阶段时序接受逻辑也必须保留并重新评估，不能只替换最后的 10 维分类层就承诺新短语有效。

尚无训练 recipe、标注语料、导出器或声学测试；没有证明外层固件/资源 CRC、签名、启动加载、ROMFS 身份或任意模型替换的完整校验链。这里明确保持 `runtime_integrity_or_signature_gate_known=false`、`custom_phrase_replacement_ready=false`。可逆资源编码不解除外层校验，更不补足原生执行、缓存发布和回滚条件。

## 下一步可测试方案

1. 若沿用原厂口令，先保留原模型：用正常界面确认 enable 完成并验证一条识别结果的 START/STOP 方向、重复说话不会反向 toggle；同时保留失败和未识别样本。Wi-Fi 设置表没有 voice key 的事实不应被改成“整机没有语音”。这一步尚未执行。
2. 主机准备音频 corpus：分别覆盖原厂成功口令、新短语、相近词、普通谈话及风噪；保留语言、说话人、距离、音量和声学真值。先明确真实 PCM 采样率、通道和标度，再对齐 400 样本特征窗、160 样本步长及 1600 样本输入块，不能用这些计数反推已验证采样率。
3. 先让原模型在主机跑通完整特征提取/两阶段推理，与同一 PCM 的原厂结果对照；再评估候选模型或独立 KWS 的召回、误触发/小时、延迟、ROM/RAM 和最坏推理时间。两条路线都输出同一 typed START/STOP，不让识别器直接调用录像 toggle。
4. 训练导出和格式预检通过后，仍需完整原厂解析/分配/数值回放、模型加载/校验和可恢复入口证据；这些闭合前不生成相机写入器。若预录后端先完成，可优先复用原厂已有 START，避免让自定义短语阻塞预录接入。
