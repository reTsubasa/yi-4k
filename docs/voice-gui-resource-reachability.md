# 相机本机语音开关的 GUI 路径与模型资源

日期：2026-11-10。范围：固定设备构建的离线 RTOS 窗口；不连接设备，不执行真实设置、识别器或资源加载器。

## 结论

当前证据支持：该构建包含已登记的语音快捷开关对象，普通下滑进入快捷页、显示对象和点击进入正常语音设置入口的代码路径均存在。不能再将它描述为“只有孤立 handler”。不过，设备实际位图资源及当前运行状态未被保存，因此还不能据此承诺真机必定显示该图标，或确认实际触摸区域。

这与 Wi-Fi 设置 API 没有登记 `voice_control` 并不矛盾：触屏入口和 API 注册表是两条不同路径。API 缺失及正常 setter 的 readiness/`vf` 条件见 [voice-settings-registration-gate.md](voice-settings-registration-gate.md)。本次没有运行真实 setter。

语音模型的两阶段拓扑和权重已从设备窗口解码，并与真实 ARM 变换指令的离线执行结果逐字节比较。模型版本名可读，但仍未找到准确中英文口令词表。`开始录像` 和 `start recording` 尚未验证；不能从分类输出维度反推口令数量或具体文字。

## 已登记的普通触屏路径

`A0181ED0` 将 D-channel 描述符表 `A06C5470` 写入初始化参数 `A0FD30C8`，并配置 `640×360` 画布、`fonts.bin` / `clut.bin` / `bitmaps.bin` / `strings.bin`。`A01816C4` 将该表交给 `A0201748`。

`*(A06C5470 + 0x15E*4) = A06BD194`，是 100 字节对象描述符：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `+0x1C` | `0x1A` | 所属快捷页组 |
| `+0x20` | `0` | 初始可见标志；显式 show 会重新设为 1 |
| `+0x21` | `4` | 位图对象 |
| `+0x24/+0x28` | `133/110` | 描述符位置 |
| `+0x2C` | `0` | 位图资源 ID |
| `+0x30` | `0x209` | 默认位图编号 |

组成员表基址 `A06B06D0`、步长 200 字节；组 `0x1A` 的记录 `A06B1B20` 明确列出 `0x15C..0x162`。语音是 `0x15E`，相邻 Wi-Fi 为 `0x15D`。

`A013D7D0` 的普通 `top_to_bot` 手势分支，在当前组 `6` 或 `0x1B`、弹窗状态不等于 `0xC`、末坐标小于 `180`、`A0199954()!=1` 等条件下调用 `A01321C0(0x1A,0,0)`。外围仍有 RTMP、LCD 唤醒、触摸阻塞和 200 ticks 去抖条件；这些运行时条件没有被宣称在实际设备上已经满足。

`A01321C0` 对该组遍历并显示成员；对语音对象按状态选择：

| 状态 | 位图 |
| --- | --- |
| 关闭、空闲 | `0x209` |
| 开启、空闲 | `0x20A` |
| 正在录像或拍照 | `0x208` |

这些分支都会 show `0x15E`；该处未发现按机型隐藏语音对象的判断。

`A0138F84` 的 group `0x1A` / object `0x15E` 分支经去抖、录像和拍照检查，调用 `A016AD30(A0FBC191 != 1)`。本次到此即由 stub 截止，没有调用会保存偏好及启停识别器的真实设置链。

通用创建链 `A02022C8 → A0200350 → A01FFB20 → A01F9FB8` 已使用真实描述符和合成有效位图元数据执行：类型 4 对象可创建，运行时可见字节设为 1，并触发创建/显示回调。该链没有额外机型过滤；这只证明控制逻辑可达。

## 位图缺口及禁止越界的边界

`A01C682C` 可以读取设备 NAND 位图缓存；缓存无效时会从 ROMFS 重新装载并调用 `A0486D50` 写缓存。因此本次没有执行该函数，也没有把它当成纯读操作。实际位图元数据/载荷读取在 `A01C7844` 等函数，输入位于未捕获的设备缓存或 ROMFS。

现存 `sys_sw_partition.bin` 为 32 MiB（SHA-256 `e3502a477701d0e3cad704adeb7e35465b89f93efe906ab0dcd3ef0a12266ce6`），包含本次 RTOS，后部大部分填充为 `ff`，没有提供设备对应的完整位图/ROMFS 内容。`artifacts/firmware/romfs/` 来自公共社区 `1.10.52`，不是固定设备 `1.10.7`，本次未将其替代为设备资源证据。

因此未证明：图标像素、宽高、最终触摸矩形、实际缓存初始化成功或当前真机屏幕状态。下一步需要对应构建的已保存 bitmap/ROMFS 资源，或用户自行观察普通下滑界面；不需要调试 bypass 来证明普通入口。

## 解码后的两阶段模型

构造函数 `A04F48D4` 将 `ctx+0x3694` 设为 `0x3FBB720F`。`A04F0048` 每个 32 位小端 word 的变换为：

```text
decoded = encoded XOR seed
seed = (decoded - seed) modulo 2^32
```

末尾不足 4 字节时仅输出有效字节；真实函数 memcpy 未覆盖的高位栈字节不确定，因此脚本只比较该次有效 seed 位，不把高位报告成可复现值。权重函数 `A04E839C` 使用同类变换并将结果交给 `A04E81A4`。本次对 8 块数据都借用真实 `A04F0048` 字节变换作对照；未执行完整权重解析器或识别器。

`A04CACD0` 的真实语言分支及构造参数封装已在合成内存中执行两次，分配器和 `A04CAA78` 构造入口被 stub。以下地址/长度与捕获参数逐项比较通过：

| 语言 | 资源 | 地址 | 字节数 |
| --- | --- | --- | ---: |
| en | stage1 graph | `A0790C60` | 4706 |
| en | stage1 weights | `A0791EC8` | 48928 |
| en | stage2 graph | `A079DDF0` | 5053 |
| en | stage2 weights | `A079F1B4` | 111239 |
| zh | stage1 graph | `A07BA43C` | 4706 |

| zh | stage2 graph | `A07C75C8` | 5053 |

第一阶段拓扑为 `AudioNIN,100,1,13`，卷积网络最后接单输出 sigmoid；第二阶段为 `AudioNIN,198,1,13`，含 `embdd_fc` 的 16 维层和 `final_fc` 的 10 维输出。两语言各阶段图结构相同，但权重不同。10 维输出不能直接解释为 10 个口令，也不能据此推断 5 对口令。

每块权重按计数、`layer:kind:`、维数、shape、float 数据解析，最后有独立 `version:` 长度和版本字符串；无多余未解释字节。两阶段各有 51、67 项张量。版本分别为 `J11_vad_model_en`、`H2_classification_model_en`、`ze_oov_vad_3`、`J11_classification_model`。

脚本对几组候选中文/英文口令进行 UTF-8、UTF-16LE 精确搜索，均未找到；这仅说明这些文字不以该编码直接存于这些解码容器中，不证明固件不支持相应说法。准确词表、类别索引到语义的映射以及实际声音识别仍是待解问题。

本次没有相机访问、持久化写入、`vc_test` 或其他调试 bypass，也没有执行位图缓存刷新。
