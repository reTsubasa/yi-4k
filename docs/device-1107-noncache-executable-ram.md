# 1.10.7 非缓存可执行 RAM：页表与所有权审计

2026-11-10。**原厂 MMU 构造结果确实包含 Normal 非缓存、XN=0 的 RAM；现有证据仍未得到可独占、可发布的首次 entry 缓冲。** 其中原厂 secondary byte pool 是可以继续研究受控分配的具体对象。这修正了“只能继续寻找通用 I-cache helper”的调查范围，没有把动态 RAM 路线直接升级为可上机探针。

本轮使用本机固定 RTOS 窗口 SHA-256 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`，base `A0100000`。没有连接相机、写设备内存/文件/分区，也没有生成 payload 或设备写入器。REA MCP 不在本会话中；证据为固定文件字节、既有 Ghidra 索引、Capstone 和 Unicorn 合成内存执行。

复现：

```sh
.venv-reverse/bin/python scripts/audit_native_mmu_entry.py
```

结果为 [audit.json](../artifacts/device/2026-11-10-native-mmu-entry-audit/audit.json)，脚本为 [audit_native_mmu_entry.py](../scripts/audit_native_mmu_entry.py)。输出目录还包含布局、构造器、初始化前缀和所有权相关代码的精确字节/反汇编。

## 从 packed 属性到真实描述符

脚本从真实 `A04A41E8` 开始，在合成 RAM 中执行原厂初始化前缀。只把读取 SCTLR 的结果声明为冷构造输入 `0`，模拟 `A04F8DEC` 的 memset，并把 `A04A22CC`/`A04A2568` 缓存操作替换为不产生硬件效果的返回。原始 `A0295CF8` 初始化器、`A04A3FB0` 分派器及其 section/small-page 构造器、正反地址转换 helper 均实际执行。

执行停在 `A04A42AC`，早于 DMB、缓存/TLB 操作和 TTBR 激活。共观察到 14 次构造调用：`A14453B0` 的 10 项本机布局，再加 `A078C0FC` 的 4 项默认设备映射。随后遍历合成 L1 的全部 4096 项及其所有 coarse L2 表，并解析真实硬件描述符；没有把 packed 字段直接当作 PTE。

| 映射范围，末端不含 | packed 属性 | 代表地址的真实 PTE | TEX/C/B | XN / AP / S | 静态含义 |
|---|---:|---:|---|---|---|
| `A064F000..A069B000` | `11603` | `0064F472`，small page | 1/0/0 | 0/3/1 | Normal non-cacheable |
| `A1B00000..A2100000` | `11601` | `01B11C02`，section | 1/0/0 | 0/3/1 | Normal non-cacheable |
| `A2100000..A3100000` | `11601` | `02111C02`，section | 1/0/0 | 0/3/1 | Normal non-cacheable |
| `A064E220`，既有 text 填充候选 | `1060F` | `0064E43E`，small page | 0/1/1 | 0/3/1 | Normal WB，no write allocate |
| `DC000000..E0000000`，Linux RAM | `1160D` | `3C011C0E`，section | 1/1/1 | 0/3/1 | Normal WB，write allocate |

small-page XN 为 bit 0，AP 在 bits 5:4 与 bit 9，TEX 在 bits 8:6，S 为 bit 10；section XN 为 bit 4，AP 在 bits 11:10 与 bit 15，TEX 在 bits 14:12，S 为 bit 16。两类 B/C 分别为 bits 2/3。`AP=3` 对应此配置下读写许可。

镜像中的 SCTLR 配置字为 `5805`；前缀按照 `A06F22FC=1` 设置高向量配置位后为 `7805`。二者 TRE、AFE、WXN 均为 0，因此这里按无 TEX remap 的 short-descriptor 属性解码，写许可不会在这一配置中自动触发 WXN。该值是构造路径的配置，不是本机当前 SCTLR 读回。实际核心的安全状态、翻译配置和后续改写仍未采集。

## 别名没有提供 text 的非缓存捷径

在这 14 项构造出的完整映射中，物理范围唯一重叠为 `PA 00100000..00104000`：虚拟 `A0100000..A0104000` 与高向量 `FFFF0000..FFFF4000`。两边都为缓存 Normal WB 映射；没有发现缓存 text 的非缓存别名。

`DC000000..DFFFFFFF` 对应 `PA 3C000000..3FFFFFFF`，为 Linux RAM 的缓存映射。`E0000000`、`E8000000`、`EF000000`、`F0000000` 的默认映射是 Strongly-ordered、XN=1，不能用作非缓存可执行 RAM 候选。不能仅凭地址形状构造 `A...`/`D...` 别名。

## 所有权把候选分成三种情况

`A064F000..A069B000` 是现有数据区。固定设备引用索引中有 1,713 条引用落入此范围，包含 VCAP 对象 `A064F3C0`、对象 `A06520C0`，以及已恢复的 DSP 发布字 `A0699160`。镜像中最长全零段为 `A065206C..A069B000`，298,900 字节；这段内本身有 260 条索引引用，包含直接写入 `A02B4310 -> A06520C8`、`A02B4318 -> A06520C4` 与 EIS 发布字写入。因此长零段明确不能整体解释为空闲空间，局部零段也没有预留证明。发布字的具体用途复用 [既有 DSP 发布审计](eis-indirect-dsp-publication-audit.md)。

`A1B00000..A2100000` 的固定地址由原厂 `A02C6C5C` 返回，四个值为 `A1B00000`、`A1F80000`、`A2000000`、`A2080000`，存在真实调用者。这些是现有资源地址；尚未恢复每块的完整生命周期，不能直接占用。其 RAM 内容也不在当前存储窗口中，不能声称为零。

`A2100000..A3100000` 有更具体的管理合同：启动函数在 `A0187654..A018766C` 构造起点 `A2100000`、长度 `01000000` 和池对象 `A0FE7220`，调用原厂 byte pool 创建包装 `A03BC6B0`。因此后续可以研究从这个池取得独立分配；该区不是一块可随意选址的 16 MiB 空闲缓冲。本轮没有调用分配器，没有取得指针或验证空闲量、最大连续块、分配对齐和生存期。已有 [readiness 查询脚本](../scripts/analyze_rtos_readiness_commands.py) 也识别到该 secondary pool，未把它当作新的用户控制入口。

## 对首次取指缺口的影响

Normal 非缓存且 XN=0 提供了比缓存 text 页尾更有根据的目标属性候选。它值得继续研究，因为可以改变代码写入与取指所需的缓存条件；当前的初始映射审计没有证明设备执行时确实保持这一属性，也没有完成具体写入者/执行者的屏障与指令同步合同。

尤其不能把“放到非缓存区”缩写为“已解决首次执行”：仍需可调用的受控分配入口、运行期页表和别名核对、代码完整写入及发布顺序、控制转移前的必要同步、固定执行核心、命令表 pointer 的独占生存期与返回撤销。若依赖分配器，最先如何调用它也仍是首次入口问题的一部分。合成 Unicorn 不模拟实际 I/D-cache、推测取指、多核或 DMA，无法证明新字节会被设备正确取指。

窄结论：**非缓存可执行 RAM 的静态候选已确认；安全、独占、可首次进入的 RAM entry 尚未确认。** 下一步离线应围绕 secondary pool 的现成调用链与所有权合同展开，而不是挑零段，或把恢复/MMU 函数内部的失效指令裁成 gadget。
