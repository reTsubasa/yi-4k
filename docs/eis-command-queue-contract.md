# EIS CPU 命令队列边界

2026-11-10。本轮继续只读收紧 `eis_update_addr` 的 CPU 传递边界。固定的 1.10.7 RTOS 镜像显示，VCAP setup 命令不是直接写 DSP 寄存器，而是经模式表间接分发到一个带就绪等待和环形槽的 0x80 字节命令队列。审计没有执行固件、没有连接相机，也没有写入 RAM、固件或分区。

```sh

```

结果保存在 [audit.json](../artifacts/device/2026-11-10-eis-command-queue/audit.json)，固定镜像 SHA-256 为 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`，16 条指令检查通过。

## 已闭合的 CPU 队列顺序

`A02BE570` 将 command code 设为 `0x08000001`，把 `VCAP_SETUP` 结构按 `0x80` 字节送入 `A02BE4C8`。`A02BE4C8` 先读取模式，再从 `A06F30F8 + mode*4` 取函数指针并间接跳转；固定表的 mode 1 项是 `A02B4858`。这确认了 CPU 侧传输有一个间接分发表，不能把固定的 mode 1 入口推广为所有运行模式的唯一消费者。

在队列状态允许时，`A02B4858` 先进入 `A02B45B4`。类型 `0x0e` 等待事件掩码 `0x00100000`，类型 `0x0d` 等待 `0x00080000`，超时参数为 1000，再读取队列基址 `+0x54` 和游标 `+0x08`。下一槽按 `0x80` 字节计算，调用 `A04F8DEC` 清零 0x80 字节，更新游标，最后调用 `A04F8D24` 复制 0x80 字节命令。容量不满足时返回 `FFFFFFFF`；通过时返回 0。这是“命令已进入 CPU 队列”的边界。

这条顺序补充了此前“命令 buffer copy”结论：队列自身有 readiness gate、游标和容量判断，但它没有给出 DSP 已锁存命令的回执。

## 当前可确认的可见性范围

在 `A02BE4C8`、`A02BE570`、`A02B45B4` 和 `A02B4858` 四个固定 ARM 窗口内，审计未发现 `dmb`、`dsb`、`isb` 或已知 D-cache helper 的直接调用。这个结果只适用于四个窗口；等待、锁、驱动和间接分发表的被调用函数另行存在，不能据此断言整个队列没有缓存或屏障协议。

`A04F8DEC` 和 `A04F8D24` 的固定实现是普通清零/复制循环。它们不包含已识别的 cache clean、DMA 完成等待或 DSP 读取确认。因此：

- queue return 只证明 CPU 队列空间检查和 0x80 字节复制路径返回；
- event wait 只证明进入队列前的就绪门，不能代替 DSP latch/ack；
- 游标递增和环绕不能证明旧命令槽、状态槽或 warp 表已经安全复用；
- `A02BE4C8` 的间接目标、底层驱动取队列时刻、cache 可见性和硬件完成顺序仍需运行期证据。

在这些边界闭合前，不把 CPU 命令入队成功升级为 EIS 表已提交，也不设计基于队列游标的自定义替换或旧槽覆盖。
