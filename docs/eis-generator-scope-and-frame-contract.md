# EIS 逐帧入口、原码生成范围与帧身份合同

本轮已将未知的 `A039C140` 两处生成调用识别为原厂 **`AmbaItuner_Execute`** 图像调参入口，并用真实 CPU 指令执行了完整 `A032CF38` 的八个受限视频场景，以及最小视频生成 helper `A032B520` 的一个独立场景。**生成算法、插值、整数/浮点数学和 Thumb memset 均未用模型替换。** 这把原 scratch 的有效点数、行距和写入范围从伪代码推断推进到了原码可复现证据。

仍没有可部署 wrapper。本轮只生成离线合成输入的结果和审计，未访问设备、修改镜像或添加写入器；未改 Android/roadmap。原生入口、缓存、恢复和实际时限关卡继续独立成立。

复现 [audit_eis_generator_scope.py](../scripts/audit_eis_generator_scope.py)：

```sh
.venv-reverse/bin/python scripts/audit_eis_generator_scope.py
```

结果 [audit.json](../artifacts/device/2026-11-10-eis-generator-scope/audit.json) 包含 26 条固定指令检查、9 个原码生成场景、4 个 theta 更新场景、每平面的写区间和 descriptor。每场景另有 `.planes.bin` 与 `.descriptor.bin`，是合成数据的原码输出，不是设备表 dump 或 payload。固定 CPU 镜像 SHA-256 为 `eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。

## 三种调用域已经分开

`A039C140` 入口把 `A06020D0` 的 `AmbaItuner_Execute` 和 `[ITUNER][DEBUG]... Execute` 传给日志，两个生成站点 `A039C4B8/A039CC70` 均在此函数内。其调用者 `A02AF2E4` 保留 `System_TuningMode` 日志及调参状态检查，另一个 `A02B1588` 是直接包装。因而这两处不是此前未识别的另一条录像 EIS producer。`A022D820` 的五处调用则属于已有 `imgcmd_warp` 测试入口。

实际 EIS 调用域是：

```text
A03AF334 → A03852F8 (EisPerFrame)
  → A0385570 → A0392CB0 (运动/网格协调器)
    → A039471C → A02D9B88 (theta 参数更新)
    → A0394740 或 A0394960 → A02DA164
      → A02DA3FC → A03119A8
        → A0311D8C → A032CF38
```

`A17045DA != 0` 走 `A0394740`，零值走 `A0394960`。后者先保存原参数快照，成功生成及 SetWarp 后还提取描述、准备原有共享 EIS 状态字段；前者的后续描述提取受调试条件控制。上层另有 `A0385504 → A02DA164` 的正常旋转测试分支，不能只凭“来自 EisPerFrame”就把所有调用当相同 EIS 模式。

继续收紧 wrapper 身份时，必须记录并限定**上游站点/分支、mode 字节及 resolved context**。`A032CF38` 的直接返回地址固定在公共包装层，对区分调参、测试、不同 EIS 模式并不充分。不能全局 hook 所有 warp 生成，再用“pipe 0”一项守卫声称只影响录像 EIS。

## Theta 的真实 ABI 与 calc_info 搬运

此前 `A02D9B88` 的 Ghidra 伪代码丢失了 VFP 参数形态。本轮原始字节确认：

```text
A039470C  vldr d16,[A17045E0]
A0394714  r0 = &mode
A0394718  vmov.f64 d0,d16
A039471C  bl A02D9B88
```

`A02D9B88` 的真实输入是 **`r0=mode 指针，d0=double theta`**。它查参数 context、获取 mutex，将保存的 `d0` 原样 `vstr` 至该参数 context `+110`，并把 `+34` 的 32 位更改计数加一，再解锁。

在 `A02DA164` 中，该 context 的 `+110/+114` 经 `LDRD` 搬到栈 `+C8`，而传给 `A03119A8` 的局部 calc_info 从栈 `+10` 开始，所以 theta 位于 **`calc_info+B8`**。这不是猜测某个普通整数参数的含义。四个原码更新场景验证了 `0、0.01、-0.125、1.25` 的 double 位图原样保存，以及更改计数的 `FFFFFFFF → 0` 回绕；context lookup 和锁在这四个小场景中明确用了替身。

`+34` 计数是**参数变更计数**，不是编码帧序号。calculation mode 中 `+4` 的 selector 也不能被改名为帧号。尤其不同校准版本和控制位决定 theta 在后续哪一步起作用，本轮不会把 `calc_info+B8` 存在，扩大成所有模式下“只改该标量便得到期望旋转”的保证。

## 输入、输出和实际有效写集

本轮完整生成场景使用原视频 pipe 0，4×4 校准输入，版本 `20140701`，X/Y tile exponent 均为 11，输入 sensor/window/CFA/main 几何一致，theta 为零。输入网格每点两个有符号 16 位值，点步长 4 字节；常量场为 `(16,-32)`，另有一个随行列变化的仿射场。原代码完成 `A032CF38 → A032B520 → A032A4B8`，并继续执行原阶段选择/更新 helper。

输出仍为原 scratch 的两个平面：X 从 `+0000` 开始，Y 从 `+1800` 开始；元素为有符号 16 位。下表是**这些精确合成 profile**的原码结果，不能跨所有 profile 外推。

| 输入几何 | X 有效列×行 | Y 有效列×行 | 行距（元素） | X/Y 实际写字节 | 原码指令数 |
|---|---:|---:|---:|---:|---:|
| 640×480 | 21×31 | 21×32 | 32 | 1302 / 1344 | 129,286 |
| 1280×720 | 21×46 | 21×48 | 32 | 1932 / 2016 | 190,605 |
| 1920×1080 | 31×35 | 31×36 | 32 | 2170 / 2232 | 211,219 |
| 3840×2160 | 31×35 | 31×36 | 31 | 2170 / 2232 | 211,245 |
| 4096×2160 | 33×35 | 33×36 | 33 | 2310 / 2376 | 224,268 |

所有常量场的有效 X 输出均为 `16`、Y 均为 `-32`；仿射 1080 场景的 X 范围为 `16..21`，Y 为 `-40..-30`。这证明输入坐标的有符号数值确实经过原插值代码流入两平面，尚不足以命名物理单位、Q 格式或像素映射方向。

descriptor 字段在这些 profile 中的对应为：

| 字段 | 原码执行对应 |
|---|---|
| `+30/+31` | X 列/行的**索引上界**，实际点数分别加一 |
| `+32/+33` | X 的两个 spacing 字节，原值保存，不扩大解释 |
| `+34` | 垂直启用字节 |
| `+35/+36` | Y 列/行索引上界，实际点数分别加一 |
| `+37/+38` | Y 的两个 spacing 字节 |

在这些测试中，CFA/main 宽度未超过 `A9C` 的普通路径保留 32 元素行距；宽幅路径使用实际列数作紧密行距。因而 1080 和 3840 虽有相同的有效点数，却不能共用同一个固定行距。

每场景先把 scratch 整个 `10000` 字节填为 `A5`，对每个原始存储指令记录写集。校准路径的写集与“有效行×列及对应行距”逐字节一致；未写到的 padding 保留 `A5`，`scratch+3000..+10000` 也保持不变。输入 calc_info 和网格在这些场景中均未改变。**不能将原厂复制每平面 `1800` 字节，理解为生成器每次填满每平面。**

两个禁用 warp 的完整场景则执行真实 Thumb memset，将两平面各 `1800` 字节清零。一个独立最小 `A032B520` 场景使用 control `8`、原始垂直启用字段和裁切 Y 值；X 全清零，Y 有效矩形为常量 `128`。该场景没有宣称完整 `A032CF38` 的对应 fake-grid/旋转预处理也已覆盖。

## 原码执行的准确范围

完整八场景没有任何函数调用 stub：原 `A032CF38`、视频生成器、插值 helper、数学库、阶段 helper 均实际执行。合成运行配置把 memcpy/memset 函数表设为已知原厂地址，其中 memset 必须为 **Thumb `A04F8DED`**；日志地址设为异常陷阱，所有通过场景均未触发日志。两个清零场景实际进入原 Thumb memset；校准场景执行 1323..2343 次真实插值 helper。

这仍是**合成输入和运行配置**。未恢复原设备完整函数表初始化、所有校准版本、异常尺寸或所有控制组合，也未证明每种 EIS 角度/滚快门 profile 的写界。启用 theta/fake-grid 的分支仍需专门完整初始化；不能靠扩大映射到任意坏地址来掩盖输入对象缺失。本轮只在有效场景内断言写范围，未将一次合成设置推广为设备全局内存安全证明。

## 帧与曝光：目前可以保留哪些身份

calc_info 的 `C0` 字节是几何、校准、控制、theta 等生成输入；本轮没有找到将编码帧号/PTS 作为独立字段传给 `A032CF38` 的证据。EIS 的关联身份在外围状态机中：

- `A1704304` 来自最近 Vin 时间状态，`A170AB5C` 在检测到新的该时间后更新，旧值保存到 `A170AEA4`。
- `A170AB38` 是 gyro 环写入索引，来自 `A1702F14`，本轮固定伪代码中可见回绕；`AB28/AB2C/AB30` 在 Vin 时间变化时保存相邻阶段的环位置。
- `A170AB1B` 等是采样子阶段，后续与 bit `100` 组成发布 tag；既有证据已证明它可重复，不能充当持久 generation ID。
- 曝光相关原厂控制包括 `A170AB14` 的 `FlgManualExposureTime` 和 `A0757AB4` 的手动曝光值。真实曝光/传感器状态还经间接回调进入采样流程，本轮未证明曝光中心或逐行曝光已直接编码进 calc_info。
- **`A17045CC` 是原厂日志称 `EisAngleLimit` 的角度限制配置，不是曝光时间。** 它参与 theta 限幅/换算，不能为了补字段而误标成 shutter。

因此下一份原厂不变的边界观测应把 producer 结果和这些**原始外围身份**一起记录：完整 mode/context、calc_info 的版本/控制/网格/geometry/theta、原返回与阶段输出、Vin 当前/上一时间、gyro 当前/相邻环索引、子阶段 tag、stock bank/两表地址及有效点指纹。没有共同单调序号或可靠时间锚时，不能把某次 scratch 输出直接绑定到 MP4 帧。

## 时限已有原厂比较点，但缺少实际余量

`A03852F8` 在 producer 协调器前后调用 `A048E3F8`，保存整个每帧计算的时间差。该 helper 的固定伪代码为读取 `A1A3A528`，与已有 filter shadow_v2 的 tick 来源相同。

原厂 `Eis-Warp calculation not in-time for ucode` 分支还有一个更具体的比较：在启用状态、`A17045DA != 0` 且 `byte(A0757AB1) != 0` 时，检查

```text
now(A048E3F8) - word(A170AB5C) >= byte(A0757AB1)
```

满足即打印超时。这个 byte 是当前配置门槛，不能从静态初值或本轮仿真时间假造真实 margin；本轮也不把 Unicorn 的 211,219 条指令换算为某个毫秒数。完整 producer 的成本随 profile 显著变化，从禁用场景约 9.5k 条到受测校准场景约 224k 条，且不包括上游运动估计、cache、调度和 DSP。

最小计时合同应记录：同一原 tick 的 producer 前/后值、外层 EisPerFrame 前/后值、Vin/AB5C 锚、当前 AB1 门槛及模式守卫。仅有平均耗时或 filter shadow_v2 的耗时，不能代替这个生成阶段及其最坏余量。shadow_v2 仍位于上游两个标量滤波调用；本轮表生成证据不会把其 88B 记录重新解释成 warp 输出。

现阶段可以审查一个**只针对已识别 EIS 视频调用、保留原生成/状态/缓冲/发布、限定到已验证有效点**的离线合同。下一次设备 wrapper 之前，仍需补齐真实 mode/geometry/profile、原函数表和 context 身份，以及同 tick 域的实际时限余量；未取得这些值时保持透明原厂路径。
