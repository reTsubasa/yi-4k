# 1.10.7 语音类别、命令语义与预录 START 边界

日期：2026-11-10。全部为固定 RTOS 镜像的静态分析和合成 ARM 执行；没有连接、配置或操控相机。

## 已恢复的映射

第二阶段虽然输出 10 维，但只有前五个类别可能产生相机命令。`A04CA540` 的 argmax 后处理只接受最大值位于前 20 字节的情况，再按表映射；其余五类返回 0。表地址由 `A04C9F24` 的 PC 相对引用恢复为 `A07E3C14`，五个 little-endian word 为 `[1002,1001,1004,1003,1005]`。

| 原始类别（从 0 开始） | 引擎公开结果 | 相机语义 | 任务发送事件 | 原厂 PCM sampling 名称 |
| --- | ---: | --- | --- | --- |
| 0 | 1002 | 连拍 | `F0010337` | `Yi_action_shoot_burst` |
| 1 | 1001 | 拍照 | `F0010336` | `Yi_action_take_photo` |
| 2 | 1004 | 停止录像 | `F0010339` | `Yi_action_stop_recording` |
| 3 | 1003 | 开始录像 | `F0010338` | `Yi_action_begin_recording` |
| 4 | 1005 | 关机 | `F001033A` | `Yi_action_turn_off` |
| 5–9 | 1000（已进入分类且未命中命令时） | 拒绝/无动作 | 不发送 | 未恢复，不命名 |

`A04CA540` 自身先返回 `1..5` 或 `0`，`A04CB57C` 再加 `1000`；尚未积累足够特征时引擎直接返回 `0`，不要与分类后的 `1000` 混淆。并列最大值时保留较早类别。后五类的训练标签没有恢复，不能擅自称它们是噪声、背景或其他口令。

采样命名表 `A056E2C8` 按公开语义顺序“拍照、连拍、开始、停止、关机”排列，和模型原始类别顺序不同。该表由 `A01B2FF8` 用来生成 PCM 文件名，语言后缀表 `A056E3F4` 为 `_en` / `_zh`。英文日志也按公开结果打印相同语义。这证明固件如何解释命令，并没有恢复声学模型的完整可说短语。

## 阈值和两阶段接受条件

实际语言构造参数已在前一份 [GUI / 模型资源审计](voice-gui-resource-reachability.md) 中通过 `A04CACD0` 的真实语言分支封装验证。阈值通过 `A04CAA78` 装入浮点寄存器 `s0` 后传给 `A04CA59C`，存入每阶段上下文 `+0x36DC`；第二阶段在总对象中对应 `+0x6DBC`。这里不能照抄 Ghidra 推断的整数函数签名。

| 语言 | 第一阶段逐输出阈值 | 第二阶段最大分数阈值 |
| --- | ---: | ---: |
| 英文 `0` | `0.6000000238418579`（`0x3F19999A`） | `0.949999988079071`（`0x3F733333`） |
| 中文 `1` | `0.5`（`0x3F000000`） | `0.9950000047683716`（`0x3F7EB852`） |

两处都使用严格 `score > threshold`，等于阈值不会接受。第二阶段比较的是网络输出分数；本文不额外假定它是经过校准的概率。

第一阶段并非任一输出超过阈值就触发：`A04C9F28` 将 13 个输出分别转为 bit，然后寻找 `1110`，即连续三个超过阈值、随后一个未超过阈值。当前实现检查起点 `0..8`；末尾起点 9 的四项没有纳入循环。合成用例已验证 `1110` 可接受、全高/全低/只有两个高/恰好等于阈值及最后一个未被扫描的起点均拒绝。这只是后处理接受条件，没有运行神经网络判断实际声音。

第一阶段未接受时 `A04CA540` 直接返回 0；接受后才执行第二阶段。第二阶段从 10 项中取全局最大值：如果最大项属于类别 5–9，即便前五类也有分数超过阈值，仍会拒绝，不会退而选前五类。

## 缓存重置与重复识别

`A04CB57C` 每次将 1600 个 16 位样本送入缓存，特征提取使用 400 样本窗口、160 样本步长。分类前要求累计特征帧数 `>120`；每次最多取最近 350 帧。这里是样本/帧计数，离线审计没有把它换算为已验证的真实时间。

分类非零（包括命令或错误）时，`A04CB568` 调用 `A04CAF98` 重新初始化前端；分类为 0 不重置。真实重置链中的 `A04CAB18` 清理音频环形缓存，`A04CD2B8` 清理特征缓冲，并将特征计数归零、相关索引复位。因此命令后不能立即用同一份特征再次输出命令，需要重新积累至少 121 帧。

这不是按类别保存上一条命令的去重表，也没有恢复出“相同命令 N 毫秒内绝不重发”的保证。持续/重复说话仍可能在重新积累后识别出同一命令。普通同配置 reset 不清零引擎累积计时 float：合成真实 reset 将其预置 7.0，执行后仍为 7.0；这不是每条口令的冷却计时器。

另有每次处理加 `0.1`、大于 `720000.0` 的长期维护重置，以及帧数极大值保护，不能将这些常量误当成短期去重窗口。初始配置的 `150.0` 和五个 `1.0` 被保存，但本轮没有证明它们是每条口令可用的动态阈值或自定义短语接口。

## 语言选择和切换同步

- shell `vc_switch_lan` 将 `en` / `zh` 明确映射为 `0` / `1`，并调用 `A01B2C30`。
- UI 资源初始化 `A01C7748` 在正常资源加载成功后，根据语言 ID 是否为 `0x404` 选择中文，否则选择英文。
- `A01B2C30` 校验语言范围，若变化则暂停任务、等待 idle、释放原引擎、重新初始化、清空两个 FIFO / 音频缓存，再恢复原 enable 标志。
- `A04CACD0` 对两语言选择不同 graph / weights 和上述阈值；原始类别到语义的五项表共用。

本次仅分析这些函数，未执行真实语言切换、UI 资源加载或设置写入。完整模型文件与边界见前一份审计。

## 从识别到录像的完整语义边界

`A01B18E0` 的任务在非 SavePCM 模式、skip 事件位 `4` 未置位时调用引擎，并将 `1001..1005` 转为上表事件。还要求当前 app 是 recorder 或另一受支持 app，且 RTMP live 标志未置位。合成任务每次只处理一份虚拟音频，再通过普通事件等待失败返回，避免无限循环。音频 FIFO、计时、引擎和事件队列均为 stub。

主消息分派的实际调用点分别为 `A019EF90 → A01B22E0`（开始）和 `A019E60C → A01B25E4`（停止）。这两条路线在语义层是独立的：

| 路线 | 前置条件与排队行为 |
| --- | --- |
| 开始 `A01B22E0` | 支持的 active app、能力位 `4`；recorder 还需 `A011F260()` ready。需要时切换 app、切换工作模式为 `4`，设置开始标志 `1`，再排队 `F001033B`，描述符保留来源 `F0010338` 和开始 pre/post callback。 |
| 停止 `A01B25E4` | 必须 recorder、工作模式 `4`、录像状态 `A0FB334C==1`。设置开始标志 `0`，排队同一 `F001033B`，但描述符来源为 `F0010339`，pre callback 也不同。 |

`A011F260` 只在状态 `0` 或 `5`、阻塞位 `A1055D08&4` 未置位、`A011EFC4()==0` 时返回 ready；录像状态 `1` 返回 0。真实 ARM 用例已确认这些状态差异。

之后公共 `F001033B` 在 `A019F66C` 的 `AMSG_CMD_VC_RECORD_BUTTON` 路线检查 active recorder 和状态字节；`A01A0958..A01A0988` 再经 app `+0x28` 回调发送 `E001000C`。`A0113808` 的 recorder handler 将其交给录像按钮逻辑。这时已不能仅凭公共按钮事件的 ID 区分 START 和 STOP。

开始回调 `A01B168C` 会再次检查 active recorder、能力与 ready；停止回调 `A01B11F8` 会再次检查模式和录像状态。直接注入共享按钮事件会跳过这些区别；在后台已经录像的预录实现里，甚至可能得到“停止”效果。

## 预录应拦截的边界

可用的最早明确语义是引擎结果 `1003`，消息层等价边界是 `F0010338`，且必须在 `A01B22E0` 的普通 ready gate 和共享 `F001033B/E001000C` 汇合之前处理。原始类别索引 `3` 可以帮助审计模型输出，但新动作层应使用明确 `START` 枚举，不依赖内部类别顺序。

建议未来的统一动作入口按状态处理：

| 状态 | START | STOP |
| --- | --- | --- |
| 空闲 | 正常开始 / 进入已配置动作 | 保持空闲 |
| 预录中 | 固定最近一分钟并继续正式录像；只 commit 一次 | 按明确产品策略结束预录或保持预录，不能隐式当作 START |
| 正在 commit | 合并/忽略重复 START | 延后到 commit 完成后处理 |
| 正式录像中 | 幂等，不停止、不 toggle | 正常停止 |

语音来源、物理快门、App 明确“开始”都应进入同一个状态机；物理按钮可以由状态机解释为 commit/stop，但不能让语音 START 直接继承物理 toggle 行为。提交中状态必须在发送异步操作前原子地锁定，才能避免两次识别或语音与快门同时到达造成重复保存。

这里是有静态证据支持的接入设计，不是已安装的固件补丁。原生代码执行/加载和安全恢复路径，以及真正的预录缓存、MP4 封装及音频并发仍须由各自研究闭合。

## 准确口令的证据边界

现有五条采样名称和英文日志支持原厂语义名称 “Yi action begin recording” / “Yi action stop recording”，但没有证明唤醒前缀、允许省略词、同义词或中文完整读法。解码出的权重是神经网络参数，不能从名称反向证明它接受用户要求的 `开始录像` / `start recording`。

本轮从控制流恢复了类别及动作，停止进行无依据的全文字符串猜测。准确读法仍需要对应原厂说明/模型训练标签等外部证据，或用户自行在相机普通界面完成声音测试；本轮没有授权或执行任何相机操作。
