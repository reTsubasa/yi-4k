# ORC `smem_2_dram` 低层传输依赖边界

日期：2026-11-11。本轮沿固定 1.10.7 ORC member 的 `smem_2_dram` 成功路径，继续追踪其直接低层 helper 和可见内存/SPR 操作。结果只说明静态字节窗口能确认到哪里；不把专有指令命名为 DMA、MMIO、barrier 或完成等待。

```sh

```

结果见 [audit.json](../artifacts/device/2026-11-11-eis-orc-transfer-dependencies/audit.json)。输入 ORC member SHA-256 为 `9b005a4fabfad2ddfeac71eca88d7968f7d2ddcc3f385d970cdbb7be12f2f1f6`，解码参考与既有 ORC 审计相同。没有执行 ORC、连接相机、访问 `/dev/mem` 或写入设备。

## 新增的有限确认

`0x1A4A04` 的直接调用目标按成功循环和错误/诊断分支分开记录。成功循环候选为 `0x1A16D8`、`0x1A16E4`、`0x1A1528`、`0x1A6EF4` 和 `0x1A15D4`；`0x1A0BFC`、`0x19FD94`、`0x19FCAC`、`0x19FE44` 等位于对齐失败、错误打印或状态处理的可见分支，不能直接当作传输引擎。

在这些有界窗口中，唯一解码出的 SPR 操作是 `0x1A16D8` 的 `l.mfspr`；没有解码出的 `mtspr`。这只证明有一个 SPR 读取依赖，不能把该寄存器读解释成 DMA 状态、MMIO 完成或硬件锁存。

`0x1A1528`、`0x1A6EF4` 和 `0x1A15D4` 的周边普通指令能确认参数预处理、描述符准备、按块循环和长度递减。实际传送点仍是未支持的专有字：描述符窗口含 `FC602007 … FC605A87 / F0000049`，读循环含 `FC606000`、`FC60001C / F0000049`，写循环含 `FC606001`、`FC600008 / F0000049`。这些字的方向、目标、完成和错误语义仍未知。

在选定的成功依赖窗口中，没有解码出指向 VCAP/shared 固定地址的标准 load/store，也没有标准 MMIO 地址常量。这是一个有界负面结果；专有字、间接表跳转和未扫描区域仍可能执行硬件传输。`smem_2_dram` 主体在对齐/零长度检查前的公共前缀中另有一个非栈 store（`r5+132`，此前可见 `r5` 被置零），本轮不为它赋予运行期地址或所有权。

## 对 EIS 反馈路径的影响

该结果把“低层依赖完全未知”收窄为：成功路径的普通控制流、对齐/分块计算和唯一可见 SPR 读取已定位；真正决定外存复制、DMA/MMIO、缓存可见性和完成时刻的专有传输窗口仍未解码。因此它支持继续做静态调用图和只读相关性设计，但不能把 `smem_2_dram` 返回、`done` 日志、共享 `+0x3C` 参数形状或 bit 清除升级为 DSP ack、硬件锁存或旧表释放屏障。

仍未知的边界包括：

- 专有 opcode 的真实格式、源/目的方向、物理目标和错误码；
- `0x1A16D8` 所读 SPR 的编号语义，以及是否参与传输完成；
- 间接 DMA/MMIO 或队列驱动是否在未扫描函数/运行期表中发生；
- 传输返回前后是否有硬件隐式等待、cache/atomic 发布或跨核可见性；
- ORC 运行期 PC/微码身份、具体帧对应关系、状态槽/warp 表最终读者和释放时刻。

所以 EIS 自定义提交门槛不变：本报告没有解除最小原生执行关卡，也没有产生可部署补丁或真机操作方案。
