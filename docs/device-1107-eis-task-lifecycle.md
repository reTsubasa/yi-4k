# YI 4K 1.10.7：EIS 任务生命周期与调度属性

本报告针对实体机固件
`Z16V13L_1.10.7_build-20180202122459_git-a8f840ce_r2746`，RTOS SHA-256 为
`eee44c6c530183ece1e3872cb3e8958919a9aa418953899dbea8b9889987381c`。结论来自本机映像
反汇编、同映像字符串交叉引用和控制流，不表示已经在真机调用这些内部函数。

## 两个 EIS 任务

| 任务 | 创建函数 | 控制块 | 入口 | 优先级参数 | 栈 | 自动启动 |
|---|---:|---:|---:|---:|---:|---:|
| `AmbaImageMainEisTask` | `0xA03975BC` | `0xA170BBB0` | `0xA0396F34` | 调用者传入，当前为 7 | `0xA0AC9200` / `0x2000` | 0 |
| `AmbaImageMainEisAlgo2Task` | `0xA0397688` | `0xA170BA90` | `0xA0396EE8` | 调用者传入，当前为 12 | `0xA0ACB200` / `0x2000` | 0 |

两个调用者分别在 `0xA03976F4` 和 `0xA03976FC` 把第二个参数先按位取反，调用者给出的
参数都是 `3`，所以传给核心排除设置入口的是 `0xFFFFFFFC`。

## 已确认的顺序

```text
0xA03BC2BC  TaskCreate(task, name, priority, entry, 0, stack, 0x2000, 0)
0xA03BC7D8  AmbaKAL_TaskSmpCoreExclusionSet(task, ~3)
0xA03BC31C  TaskResume(task)
```

`0xA03BC7D8` 的实现是 `0xA03C0BC4` 的跳板。它检查 `THRD` 魔数，在控制块 `+0x98`
保留高位并写入传入值的低两位；`0xA03BC7DC` 读取同一字段的低两位。固件字符串中有
`AmbaKAL_TaskSmpCoreExclusionSet` 的失败日志，多个非 EIS 子系统也用同样的
`~(value & 3)` 形式调用，因而“核心排除掩码”是高置信名称。掩码各位与物理 CPU 编号的
精确对应仍未恢复。

创建检查层 `0xA03C4240` 将 `auto_start` 传到 `0xA03BFC90`。后者在参数为 0 时只完成
控制块登记，状态置为 3，不把线程插入 ready 队列；参数非 0 才调用 `0xA03C17C4`
进入调度。`0xA03BC31C` 经 `0xA03C4644` 在状态为 3 时调用同一个调度函数，所以在
EIS 路径中它是启动/恢复操作。独立调用者 `0xA0188944` 在这一步失败时打印
`can not resume task`，与控制流结论相互印证。此前把它描述成“挂起”是错误的，已在任务
模板中更正。

## 入口返回与回收

创建层把 entry 和参数保存到控制块 `+0x44`、`+0x48`。调度到线程时，
`0xA03C0A74` 执行：

```c
entry = *(void (**)(uint32_t))(task + 0x44);
arg   = *(uint32_t *)(task + 0x48);
entry(arg);
```

entry 返回后，外层把状态字段 `+0x30` 和完成字段 `+0x38` 写为 1，调用控制块的退出
通知回调及全局退出通知，然后通过 `0xA03C1D5C` 将线程从当前调度结构移除。控制块的
`THRD` 魔数不会在这里自动清零，`TaskDelete` 也不会自动发生；“函数返回”只代表线程
结束并脱离调度，不能代表对象和栈已经可以复用。

目前静态映像中可区分的管理入口为：

| 入口 | 当前结论 |
|---|---|
| `0xA03BC30C` | 删除并从全局线程链摘除控制块；清除 `THRD` 魔数 |
| `0xA03BC310` | 终止活动线程，触发终止回调和调度清理 |
| `0xA03BC318` | 挂起/从 ready 结构移除 |
| `0xA03BC31C` | 恢复/把初始状态 3 放入 ready 结构 |

这些入口均未在真机上调用。最小 payload 的安全设计应让 entry 只写一次标记后返回，
由外部控制路径在确认返回后调用 `TaskDelete`；不要在 entry 内删除自身，也不要把栈或
控制块放在临时 `loadbin` 缓冲区后立即覆盖。

## 对二开的直接影响

最小原生扩展的任务生命周期应按以下顺序设计：

1. 获得有明确所有权的 `0xD8` 控制块、静态栈和常驻入口。
2. `TaskCreate(..., auto_start=0)`。
3. 设定核心排除掩码；不要把掩码直接当成 CPU affinity 编号。
4. 明确检查返回值后再 `TaskResume`。
5. 入口只做有限日志或计数，验证返回、栈和原厂录像健康，再研究 EIS hook。

仍不能从 Linux 直接调用这些地址，也不能复用 `0xA170BBB0`、`0xA170BA90` 或原厂栈。
`loadbin` 仍然只负责读文件；这个生命周期分析没有打通 payload 的加载、缓存同步和调用
入口。
